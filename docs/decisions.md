# Decisions

## K12 · 2026-11-17: устройство реестра команд (next)

By: agent · Area: архитектура · Status: active · Reviewed: no
Source: during M0.2

Реестр — `createRegistry<State>(getState)` с тремя методами: `register`, `run(id, params)`,
`list()`. Выбрано без человека:

- Параметры описываются простыми данными (`string`, `integer`, `number`, `boolean`, `enum`), а не
  функцией разбора: описание уходит в `list()` и через канал управления как JSON, а тип
  аргумента `run` выводится из описания. Своя проверка на 190 строк вместо библиотеки схем (L3).
- Значения не приводятся (`"3"` — не число), лишний параметр — ошибка. Разбор строки адреса —
  дело маршрутизатора, он передаёт в команду уже числа.
- `run` реестра не бросает исключений и возвращает `{ ok }` или ошибку простыми данными с кодом
  (`unknown-command`, `invalid-params`, `disabled`, `failed`); `register` бросает
  `CommandDefinitionError` (`duplicate-id`, `invalid-definition`), потому что это ошибка в коде, а
  не во входных данных, и её должен поймать gate.
- Команды синхронные: результат сразу, детерминизм (M0.4) проще. Долгая работа отражается в
  состоянии. Пересмотреть в M1.3, если плееру понадобится ждать завершения команды.
- Название команды — ключ текста (`titleKey`), сами тексты появятся с i18n (M2).
- Сужение типа проверенных параметров сделано функцией-предикатом, которая заново проверяет
  объект; `as` и `!` в `src/commands` нет.

## K11 · 2026-11-17: состав gate в M0.1 (next)

By: agent · Area: стек · Status: active · Reviewed: no
Source: during M0.1

`npm run gate` = prettier, eslint (strictTypeChecked, запрет `!` и `any`), svelte-check, vitest,
`scripts/structure-check.mjs`, сборка. Проверка слоёв написана своим скриптом на 130 строк
вместо dependency-cruiser: правил три, зависимость не нужна; тот же скрипт проверяет, что в
`content/` нет кода и что код сайта не ссылается на чужие серверы (L6). Prettier не трогает
`*.md` (в плане рукописные таблицы) и `prototype/`. Playwright входит в gate с M0.3, проверка
лицензий зависимостей — с M4.4. Версии инструментов — последние на дату установки
(TypeScript 6, Vite 8, ESLint 10, Vitest 5), закреплены в `package-lock.json`.

## K10 · 2026-11-17: уроки и переводы в YAML, выпуски через GitHub, сайт на Cloudflare (chat)

By: owner · Area: стек · Status: active · Reviewed: yes
Source: chat

Владелец попросил хранить схемы атак в репозитории в открытом формате, чтобы любой мог добавить
или поправить урок и язык через pull request, выпускать версии через GitHub и выкладывать
статику на Cloudflare на его домене. Решение: `content/lessons/<id>/lesson.yaml` (схема урока

уроки и переводы; тег версии создаёт GitHub Release и выкладывает сайт. Заменяет K2 в части
хостинга (Vercel) и запись архитектуры `lesson.ts`. Svelte 5, Vite и TypeScript из K2 остаются.
Вид сервиса Cloudflare (Pages или Workers со статикой) выбирается в M0.5.
