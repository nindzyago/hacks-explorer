## K17 · 2026-11-17: устройство детерминизма (M0.4)

By: agent · Area: архитектура · Status: active · Reviewed: no
Source: during M0.4

- Часы: `src/core/clock.ts`, целые миллисекунды, шаг 10 мс, остаток копится. `set` — перемотка
  без шагов с одним событием `set`. Ошибки — простые данные с кодом, без исключений. Не больше
  1000 шагов за `tick`, не больше 24 часов всего.
- Часы живут в `AppContext` рядом с хранилищем, а не в `AppState`: шаг каждые 10 мс не должен
  будить подписчиков хранилища. `state.get()` канала отдаёт снимок часов полем `clock`.
- Драйвер реального времени: каталог-адаптер `src/time` (L3). `src/main.ts` запускает его в
  любой сборке. Первая принятая команда `clock.set` / `clock.tick` останавливает его насовсем;
  пуск и паузу свяжет с ним плеер в M1.3.
- Запрет системного времени и случайных чисел в `src/` — правилами ESLint, кроме файла драйвера
  и тестов. Комментарием не выключается (`noInlineConfig`); исключения только в конфиге. Сверх
  задания запрещены `svelte/motion`, `svelte/transition`, `svelte/animate`, `SvelteDate`,
  Web Animations, `crypto.randomUUID`. Это защита от случайной ошибки, не от умысла; обходы
  перечислены в `src/time/README.md`. CSS-анимации правилами не видны — проверка нужна в M1.2.
- Дамп состояния: свой сериализатор с ключами в порядке кодов UTF-16; ошибка вместо
  молчаливого `null`; `toJSON` не вызывается; объекты, только похожие на простые, отклоняются.
- Строка «Часы плеера» видна только в dev и e2e сборках, чтобы снимок зависел от времени
  часов, пока нет сцены. Убрать, когда появится сцена (M1.2).
- Повторяемый сценарий в браузере должен начинаться с `clock.set(...)`: до первой ручной
  команды часы уже шли от реального времени.

## K15 · 2026-11-17: канал управления и отдельная сборка для тестов (M0.3)

By: agent · Area: стек · Status: active · Reviewed: no
Source: during M0.3

`window.__app` включается условием в `src/main.ts`: `import.meta.env.DEV` или режим `e2e`.
Тесты идут на отдельной сборке `vite build --mode e2e --outDir dist-e2e`, которая отличается
от рабочей только этим флагом. Папка отдельная, чтобы сборка с каналом не могла попасть в
выкладку из `dist/`. Отсутствие канала в рабочей сборке проверяет e2e-проект `production`:
нет строки `__app` в файлах `dist/`, нет `window.__app` в браузере. Канал отдаёт копии,
заморожен, `commands.run` не бросает исключений.

## K14 · 2026-11-17: Cloudflare Workers со статикой и Workers Builds, а не Pages (M0.5)

By: agent · Area: стек · Status: active · Reviewed: no
Source: during M0.5, документация developers.cloudflare.com на 2026-11-17

Выбраны Workers со статическими ассетами. Причины: Cloudflare на странице Pages советует
начинать новые проекты на Workers; всё нужное есть — сборка по событиям GitHub через приложение
Cloudflare без токена в GitHub, основная ветка задаётся в настройках и может быть не `main`,
остальные ветки и pull request получают адрес предпросмотра и комментарий в PR, `_headers` и
отдача `index.html` на неизвестные адреса поддержаны, свой домен подключается одной настройкой.
Лимиты бесплатного тарифа: 3000 минут сборки в месяц, одна сборка за раз, 100 предпросмотров.
Схема веток: сейчас основная ветка в Cloudflare — `main`, черновой адрес
`hacks-explorer.<поддомен>.workers.dev`; в M4.6 основной станет `release`. `hacks.antipic.com`
в `wrangler.jsonc` не записан и подключается в панели в M4.7, чтобы первая выкладка не
опубликовала сайт без решения владельца (L3); защитный тест запрещает `routes` в конфигурации.
Заголовки: строгая CSP только на свой origin без `unsafe-inline`, `img-src` разрешает `data:`;
HSTS — настройка зоны владельца. Node для сборки закреплён файлом `.node-version` (22).
`wrangler` в зависимости не добавлен: вместе с ним приходят необязательные пакеты с лицензиями
вне списка L1 (LGPL-3.0 у `@img/sharp-libvips-*`, CC0-1.0 у `@speed-highlight/core`); сборка
Cloudflare берёт последний wrangler через `npx`, версия не закреплена (gap G13). Сборка
pull request из форков для Workers Builds в документации не описана. Уточняет K10 и K12.

## K13 · 2026-11-17: устройство реестра команд (next)

By: agent · Area: архитектура · Status: active · Reviewed: no
Source: during M0.2

Реестр — `createRegistry<State>(getState)` с тремя методами: `register`, `run(id, params)`,
`list()`. Выбрано без человека:

- Параметры описываются простыми данными (`string`, `integer`, `number`, `boolean`, `enum`), а не
  функцией разбора: описание уходит в `list()` и через канал управления как JSON, а тип
  аргумента `run` выводится из описания. Своя проверка на 190 строк вместо библиотеки схем (L3).
- Значения не приводятся (`"3"` — не число), лишний параметр — ошибка. Разбор строки адреса —
  дело маршрутизатора, он передаёт в команду уже числа.
- `run` реестра не бросает исключений и возвращает `{ ok }` или ошибку простыми данными с кодом
  (`unknown-command`, `invalid-params`, `disabled`, `failed`); `register` бросает
  `CommandDefinitionError` (`duplicate-id`, `invalid-definition`), потому что это ошибка в коде, а
  не во входных данных, и её должен поймать gate.
- Команды синхронные: результат сразу, детерминизм (M0.4) проще. Долгая работа отражается в
  состоянии. Пересмотреть в M1.3, если плееру понадобится ждать завершения команды.
- Название команды — ключ текста (`titleKey`), сами тексты появятся с i18n (M2).
- Сужение типа проверенных параметров сделано функцией-предикатом, которая заново проверяет
  объект; `as` и `!` в `src/commands` нет.
