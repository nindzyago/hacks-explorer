# src/core/lesson — формат урока и проверка

Слой L0. Урок — один Markdown-файл на язык: `content/lessons/<id>/<язык>.md` (K18, K21).
Модуль превращает текст файла в данные урока и находит ошибки. Чистый: строка на входе, данные
на выходе, без файловой системы и без исключений. Файлы читает `scripts/content-files.mjs`.
Разбор Markdown — пакет `mdast-util-from-markdown` (дизайн M1.1, E2).

Это зерно руководства автора (M4.1).

## Формат 1 на примере

````markdown
# SQL-инъекция

`lesson` B1 · `section` B · `wave` 1 · `format` 1

## Паспорт

- `cwe` 89
- `owasp` A03:2021
- `severity` critical
- `impact` Вход под чужой учётной записью
- `defence` Параметризованный запрос

## Источники

- [MITRE CWE-89: SQL Injection](https://cwe.mitre.org/data/definitions/89.html)

## Участники

- `attacker` **Атакующий** — 203.0.113.66
- `server` **Веб-сервер** — 198.51.100.10
- `db` **База данных** — таблица users · `icon:database`

## Зоны

- `internet` Интернет: `attacker`
- `site` Сайт shop.example: `server`, `db`

## Шаги

### `glue` Сервер склеивает запрос

`server → db` · `attack` · `without-defence`
Сообщение: SELECT ... · Итог: атака

```sql
WHERE login = '⟦admin' --⟧'
```

#### Просто

Сервер **вклеивает** ввод прямо в запрос.

#### По шагам

…

#### Глубже

…

### `refuse` Отказ

`server → attacker` · `safe` · `with-defence` · `stopped`
Сообщение: Неверный вход · Итог: остановлено

#### Просто
…

## Как защититься

Передавайте данные отдельно от запроса.
````

Полный настоящий урок: `content/lessons/B1/ru.md`.

Порядок разделов фиксирован: Паспорт, Источники, Участники, Зоны, Шаги, Как защититься.

### Шаг

- Служебная строка: `` `откуда → куда` · `вид` `` и по желанию пометки через ` · `.
  Вид: `legit` (обычное сообщение), `attack` (вредное), `safe` (защищённое).
  Пометки: `with-defence` — шаг только в режиме «С защитой», `without-defence` — только «Без
  защиты», без пометки — в обоих (K20); `stopped` — защита остановила сообщение, только вместе с
  `with-defence`; `` `icon:имя` `` — иконка таблички. Откуда и куда — id участников; можно
  `` `attacker → attacker` `` (действие на месте).
- Строка таблички: `Сообщение: … · Итог: …` — простой текст, Markdown в ней не разбирается.
- Блок кода между служебными строками и первым уровнем — код шага, виден на любом уровне.
  `⟦…⟧` выделяет вредную часть; пометки парные, не вложенные, не пустые, только внутри блоков
  кода.
- Три уровня `#### Просто`, `#### По шагам`, `#### Глубже` — все три у каждого шага, в этом
  порядке, непустые (K22). Блок кода внутри уровня — часть текста этого уровня.

### Текст

В уровнях и в «Как защититься»: абзацы, списки (обычные и нумерованные), **жирный**, *курсив*,
`код в строке`, блоки кода. Запрещены HTML, картинки, ссылки (они только в «Источниках»),
цитаты, заголовки внутри текста, горизонтальные линии. Сайт показывает текст своими
компонентами, HTML не вставляет.

Однострочные поля — заголовок урока, строка урока, паспорт, участники, зоны, заголовок и две
строки шага — простой текст: только слова и служебные слова в обратных кавычках (у участника ещё
**имя**). HTML, картинки, ссылки, курсив и жирный в них — ошибка; текст, который браузер принял
бы за тег (`<b`, в том числе записанный как `&lt;b`), — ошибка `html`.

### Файл

Кодировка UTF-8. Начальный BOM отбрасывается; концы строк CRLF и одиночный CR читаются как LF,
номера строк и столбцов совпадают с тем, что видно в редакторе.

### Урок об атаке

Урок — об атаке, если хотя бы один шаг имеет вид `attack`. Тогда нужны шаг `with-defence`,
раздел «Как защититься», `defence` и `severity` в паспорте (L4.3). Урок без вредных сообщений
(например, «Шифрование») этих правил не имеет.

### Адреса

Все IP-адреса и домены во всём файле, включая код, заметки и подписи зон, — только учебные:
192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24, 2001:db8::/32, example.com, example.org,
example.net и всё в `.example`, `.test`, `.invalid`, `.localhost` (L4.2). Исключение — ссылки
в «Источниках» целиком (название и адрес): они ведут на настоящие сайты.

Правило (эвристика, `addresses.ts`):

1. Текст сначала нормализуется: NFKC (полноширинные точки и цифры `．` `８` → `.` `8`) и без
   невидимых знаков нулевой ширины. Позиция в ошибке — в исходном тексте.
2. IPv4 и IPv6 проверяются везде. IPv6 узнаётся и после `слово:` (`addr:2606:4700::1111`), но
   не внутри идентификаторов (`std::string`); время `12:30:45` и `A03:2021` адресами не считаются.
3. Имя через точку считается хостом, если выполнено хотя бы одно:
   - оно стоит как адрес: после `схема://` или `@`, начинается с `www.`, за ним `:порт` или
     `/путь`;
   - в нём есть метка punycode `xn--`;
   - в нём смешаны латиница и кириллица (`google.сom` с кириллической «с»);
   - оно кончается зоной из списка явных хостовых зон: `com net org edu gov mil biz ru su рф рус
     ua by kz uk de fr cn jp kr br ca au nl es se ch eu us io co tv xyz tech zip mov ai cc gg ly
     icu buzz cfd sbs`;
   - оно кончается зоной, любимой фишингом, но похожей на поле в коде: `app dev site store shop
     top info online me to it in pl pw live click vip club link` — и не похоже на код. Похоже на
     код, если:
     - **все** метки перед зоной — «получатели» (без учёта регистра):
       объекты JS и Python `this self cls super window document navigator globalThis process
       module exports console logger log logging req res request response ctx context app config
       settings options opts props state store vm os sys System path event err error el elem
       element node style rect bounds offset pos position box stack parent item items data user
       status btn`; файлы сборки `Makefile Dockerfile configure setup requirements MANIFEST`;
       элементы HTML в селекторах CSS `a abbr article aside b body button canvas code dd div dl
       dt em footer form h1–h6 header html i img input label li main nav ol option p pre section
       select small span strong table tbody td textarea th thead tr ul`. В шаблоне сборки
       `имя.<расширение>.in` метка перед `in` может быть расширением (`h c py cfg txt json yml
       yaml toml ini conf xml mk am`): `config.h.in`, `setup.py.in`;
     - или имя из двух меток и сразу за ним, без пробела, стоит `(` или `[`: `tensor.to(device)`,
       `items.shop[0]`.

     Так `bit.ly`, `t.me`, `paypal.me`, `evil.top`, `x.vercel.app`, `evil.pages.dev`,
     `this.evil.top` (чужая метка в цепочке), `login.evil.top[0]` (больше двух меток),
     `evil.top (там форма)` (пробел перед скобкой) — хосты, а `window.top`, `this.props.store`,
     `logger.info`, `logging.info(…)`, `navigator.onLine`, `System.in`, `Makefile.in`,
     `MANIFEST.in`, `requirements.in`, `Dockerfile.dev`, `div.app`, `span.info`, `offset.top` —
     код.
4. Прочие имена через точку — идентификаторы и файлы: `users.id`, `u.email`, `this.name`,
   `file.py`, `ru.md`, `libc.so`, `run.sh`, `main.rs`. Зоны, которые совпадают с частыми полями и
   расширениями (`id`, `py`, `md`, `so`, `sh`, `rs`, `js`, `name`, `email`, `date` и прочие не из
   списков), считаются хостом только в положении адреса (пункт 3, первый вариант).

Известные совпадения (ошибка `address` на коде; пишите иначе или в положении, где ясно, что это
код): `main.cc` (файл C++ — зона `cc`), `run.pl` (скрипт Perl — `pl`), поле объекта с
незнакомым получателем: `cart.store`, `game.top`, `user2.info`, `ctx2.app`, `post.link`,
`page.live`, `team.club`. Получатель из списка и вызов спасают: `this.store`, `cart.store()`.

Ограничения правила: `evil.lol` или `evil.id` без `www.`, схемы, `@`, порта и пути не
распознаются; хост с зоной второго списка, у которого все метки перед зоной — получатели
(`app.store`, `user.me`, `a.info`), или имя из двух меток, за которым вплотную стоит `(` или `[`
(`evil.top[1]`, `evil.link(x)`), не распознаётся; IPv4 целым числом
(`134744072`) и в восьмеричной или шестнадцатеричной записи не распознаётся; омоглифы из других
алфавитов, кроме кириллицы, не ловятся. Их найдёт ревью.

## API

```ts
import { checkContent, checkLesson, formatError } from './check';

const { lesson, errors } = checkLesson('content/lessons/B1/ru.md', text, {
  sourceDomains: ['owasp.org', 'mitre.org'],
});
// lesson — данные урока (types.ts) только если errors пуст

const result = checkContent(files, { path: 'content/sources.md', text: sourcesText });
// result.lessons — уроки без ошибок; result.errors — все ошибки, в том числе сверка переводов
result.errors.map(formatError); // 'content/lessons/B1/ru.md:41:1: step `glue`: …'
```

Ошибка — данные `{ file, line, column, path, code, message }`. `path` — где в уроке:
`steps.glue.deep`, `zones.site`, `passport.cwe`. Сообщения на английском, называют строку и
показывают правильный вид. Внутри файла ошибки идут по номеру строки; больше 100 — остальные
считаются одной ошибкой `too-many-errors`.

### Пределы и скорость

До разбора Markdown проверяются дешёвые пределы, чтобы никакой файл не заставил разборщик
работать долго (он тратит квадратичное время на длинные цепочки некоторых конструкций):

| предел | значение | что без него |
|---|---|---|
| размер | 64 КБ в UTF-8 | — |
| строк | 1000, как их нумерует редактор: перевод строки в конце файла новой строки не начинает (B1 — около 220) | 16 000 setext-заголовков `a` / `=` — 14 с |
| знаков `*` `_` `[` | 2000 (B1 — около 60) | 16 000 знаков выделения — 1,2 с |
| маркеров `>` `-` `+` `*` `1.` в начале строки | 2, и последний не дальше 16-го столбца | 64 000 `>` — 4 с; 2000 строк `- - - - a` — 0,9 с; список, вложенный отступами на 200 уровней, — 0,4 с |

Худший замеренный случай после пределов — около 180 мс на этом Mac (1000 строк setext-заголовков
`a` / `-`; обычно до 120 мс; перебрано около 45 видов враждебных файлов до 64 КБ, два прогона).
Отступ без маркеров (код внутри блока) не ограничен.

Границы закреплены тестами `limits.test.ts` на самом пределе и на единицу дальше: 65 536 байт
проходят, 65 537 нет (и латиницей, и кириллицей); 1000 строк проходят с переводом строки в конце
и без него, 1001 нет; 2000 знаков `*` `_` `[` вместе проходят, 2001 нет; два маркера (`> >`,
`1. 1.`, `> -`) проходят, три нет; маркер, который кончается в 16-м столбце (табуляция — 4
столбца), проходит, в 17-м нет.

## Переводы и новый язык

`ru.md` — основа. Файл другого языка проверяется так же и сверяется с `ru.md`: строка урока,
коды паспорта (`cwe`, `owasp`, `attack`, `cvss`, `cves`, `severity`, наличие `defence`),
участники (id и иконки по порядку), зоны (id, состав, `danger`), шаги (id по порядку, откуда,
куда, вид, пометки, иконка), наличие «Как защититься». Тексты, подписи, источники и код не
сверяются. Пока перевода нет, правило ничего не делает. Если в `ru.md` ошибки, сверка ждёт их
исправления.

Заголовки разделов и уровней и подписи «Сообщение»/«Итог» берутся из таблицы `headings.ts` по
языку из имени файла. Английский там уже есть (`Passport`, `Sources`, `Participants`, `Zones`,
`Steps`, `How to defend`; `Simple`, `Step by step`, `Deeper`; `Message`, `Result`), поэтому
`en.md` добавляется без изменений кода. Третий язык — одна запись в `headings.ts`.

## Ограничения

- Пределы выбраны по замерам скорости на враждебных файлах и по B1 (около 9 КБ, 220 строк);
  на других настоящих уроках не проверялись.
- Подпись зоны не может содержать двоеточие перед списком участников; имя участника — без `*`.
- Набор иконок не сверяется с `content/icons` (иконок ещё нет, M1.2): проверяется только вид
  имени.
- Номера CWE и CVE проверяются по виду, не по NVD и MITRE (сверка фактов — верификатор, L5).
- `parseLesson` получает уже разобранное дерево; модуль тянет `mdast-util-from-markdown`, поэтому
  в браузерную сборку его не импортируют — данные собирает сборка (M1.1b).
