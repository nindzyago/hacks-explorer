# src/core/lesson — формат урока и проверка

Слой L0. Урок — один Markdown-файл на язык: `content/lessons/<id>/<язык>.md` (K18, K21).
Модуль превращает текст файла в данные урока и находит ошибки. Чистый: строка на входе, данные
на выходе, без файловой системы и без исключений. Файлы читает `scripts/content-files.mjs`.
Разбор Markdown — пакет `mdast-util-from-markdown` (дизайн M1.1, E2).

Это зерно руководства автора (M4.1).

## Формат 1 на примере

````markdown
# SQL-инъекция

`lesson` B1 · `section` B · `wave` 1 · `format` 1

## Паспорт

- `cwe` 89
- `owasp` A03:2021
- `severity` critical
- `impact` Вход под чужой учётной записью
- `defence` Параметризованный запрос

## Источники

- [MITRE CWE-89: SQL Injection](https://cwe.mitre.org/data/definitions/89.html)

## Участники

- `attacker` **Атакующий** — 203.0.113.66
- `server` **Веб-сервер** — 198.51.100.10
- `db` **База данных** — таблица users · `icon:database`

## Зоны

- `internet` Интернет: `attacker`
- `site` Сайт shop.example: `server`, `db`

## Шаги

### `glue` Сервер склеивает запрос

`server → db` · `attack` · `without-defence`
Сообщение: SELECT ... · Итог: атака

```sql
WHERE login = '⟦admin' --⟧'
```

#### Просто

Сервер **вклеивает** ввод прямо в запрос.

#### По шагам

…

#### Глубже

…

### `refuse` Отказ

`server → attacker` · `safe` · `with-defence` · `stopped`
Сообщение: Неверный вход · Итог: остановлено

#### Просто
…

## Как защититься

Передавайте данные отдельно от запроса.
````

Полный настоящий урок: `content/lessons/B1/ru.md`.

### Части файла

| Что | Как пишется | Обязательно |
|---|---|---|
| Заголовок | `# Название` — первая строка | да |
| Строка урока | `` `lesson` B1 · `section` B · `wave` 1 · `format` 1 `` сразу после заголовка. `lesson` равен имени папки, `section` — первой букве id, `wave` 1–3, `format` только 1 | да |
| Паспорт | список `` - `слово` значение ``. Порядок разделов фиксирован: Паспорт, Источники, Участники, Зоны, Шаги, Как защититься.

### Шаг

- Служебная строка: `` `откуда → куда` · `вид` `` и по желанию пометки через ` · `.
  Вид: `legit` (обычное сообщение), `attack` (вредное), `safe` (защищённое).
  Пометки: `with-defence` — шаг только в режиме «С защитой», `without-defence` — только «Без
  защиты», без пометки — в обоих (K20); `stopped` — защита остановила сообщение, только вместе с
  `with-defence`; `` `icon:имя` `` — иконка таблички. Откуда и куда — id участников; можно
  `` `attacker → attacker` `` (действие на месте).
- Строка таблички: `Сообщение: … · Итог: …` — простой текст, Markdown в ней не разбирается.
- Блок кода между служебными строками и первым уровнем — код шага, виден на любом уровне.
  `⟦…⟧` выделяет вредную часть; пометки парные, не вложенные, не пустые, только внутри блоков
  кода.
- Три уровня `#### Просто`, `#### По шагам`, `#### Глубже` — все три у каждого шага, в этом
  порядке, непустые (K22). Блок кода внутри уровня — часть текста этого уровня.

### Текст

В уровнях и в «Как защититься»: абзацы, списки (обычные и нумерованные), **жирный**, *курсив*,
`код в строке`, блоки кода. Запрещены HTML, картинки, ссылки (они только в «Источниках»),
цитаты, заголовки внутри текста, горизонтальные линии. Сайт показывает текст своими
компонентами, HTML не вставляет.

### Урок об атаке

Урок — об атаке, если хотя бы один шаг имеет вид `attack`. Тогда нужны шаг `with-defence`,
раздел «Как защититься», `defence` и `severity` в паспорте (L4.3). Урок без вредных сообщений
(например, «Шифрование») этих правил не имеет.

### Адреса

Все IP-адреса и домены во всём файле, включая код, заметки и подписи зон, — только учебные:
192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24, 2001:db8::/32, example.com, example.org,
example.net и всё в `.example`, `.test`, `.invalid`, `.localhost` (L4.2). Исключение — адреса
ссылок в «Источниках»: они ведут на настоящие сайты.

Проверка эвристическая: домен — имя через точку, которое кончается настоящей зоной (`com`,
`org`, `ru`, `io`, все двухбуквенные зоны стран и частые общие). Поэтому `users.id` и `file.py`
тоже считаются доменами (`.id` и `.py` — зоны стран): пишите `id` без имени таблицы или
перефразируйте. `Node.js` и `index.html` доменами не считаются. Редкие общие зоны (`.lol`) не
распознаются.

## API

```ts
import { checkContent, checkLesson, formatError } from './check';

const { lesson, errors } = checkLesson('content/lessons/B1/ru.md', text, {
  sourceDomains: ['owasp.org', 'mitre.org'],
});
// lesson — данные урока (types.ts) только если errors пуст

const result = checkContent(files, { path: 'content/sources.md', text: sourcesText });
// result.lessons — уроки без ошибок; result.errors — все ошибки, в том числе сверка переводов
result.errors.map(formatError); // 'content/lessons/B1/ru.md:41:1: step `glue`: …'
```

Ошибка — данные `{ file, line, column, path, code, message }`. `path` — где в уроке:
`steps.glue.deep`, `zones.site`, `passport.cwe`. Сообщения на английском, называют строку и
показывают правильный вид. Внутри файла ошибки идут по номеру строки; больше 100 — остальные
считаются одной ошибкой `too-many-errors`.

| code | когда |
|---|---|
| `bad-path` | путь не `content/lessons/<id>/<язык>.md`, id не вида `B1` |
| `unknown-language` | язык из имени файла не в `headings.ts` |
| `too-large` | файл больше 64 КБ (в байтах UTF-8); не читается дальше |
| `too-complex` | больше 2000 знаков `*`, `_`, `[` — разборщик тратит на них квадратичное время |
| `too-deep` | вложенность текста глубже 16 |
| `parse-failed` | не текст |
| `unexpected-file` | в папке урока что-то кроме `<язык>.md` |
| `missing-title`, `bad-header` | нет `# Названия` или строки урока |
| `unknown-word` | неизвестное служебное слово в строке урока, паспорте, шаге |
| `bad-value` | неверное значение: id, номер формата, CWE, вектор CVSS, иконка… |
| `duplicate` | раздел, уровень, слово, участник, зона или шаг повторяются |
| `unknown-section`, `missing-section`, `section-order` | раздел не из таблицы, обязательного нет, порядок нарушен (и порядок уровней) |
| `sandbox-not-allowed` | раздел «Песочница» (E10: место под G2) |
| `stray-content`, `bad-line` | текст не на своём месте; строка не того вида |
| `empty-section` | раздел есть, но пуст |
| `html`, `image`, `link`, `not-allowed` | запрещённое в тексте (E4) |
| `bad-mark` | ⟦…⟧ непарные, вложенные, пустые или вне блока кода |
| `unknown-level`, `missing-level` | уровень не из трёх; уровня нет или он пуст |
| `unknown-participant` | шаг или зона ссылаются на неизвестного участника |
| `too-many-participants` | больше шести участников |
| `zone-not-contiguous`, `zone-overlap` | зона не из соседей; участник в двух зонах |
| `stopped-without-defence` | `stopped` без `with-defence` |
| `no-defence-step`, `no-defence-section`, `no-defence-name` | урок об атаке без шага защиты, раздела «Как защититься», `defence` или `severity` |
| `no-sources`, `source-domain` | «Источники» пусты; ссылка не https или не на разрешённый домен |
| `address` | IP или домен вне учебных |
| `missing-base`, `translation-mismatch` | перевод без `ru.md`; служебное расходится с `ru.md` |

## Переводы и новый язык

`ru.md` — основа. Файл другого языка проверяется так же и сверяется с `ru.md`: строка урока,
коды паспорта (`cwe`, `owasp`, `attack`, `cvss`, `cves`, `severity`, наличие `defence`),
участники (id и иконки по порядку), зоны (id, состав, `danger`), шаги (id по порядку, откуда,
куда, вид, пометки, иконка), наличие «Как защититься». Тексты, подписи, источники и код не
сверяются. Пока перевода нет, правило ничего не делает. Если в `ru.md` ошибки, сверка ждёт их
исправления.

Заголовки разделов и уровней и подписи «Сообщение»/«Итог» берутся из таблицы `headings.ts` по
языку из имени файла. Английский там уже есть (`Passport`, `Sources`, `Participants`, `Zones`,
`Steps`, `How to defend`; `Simple`, `Step by step`, `Deeper`; `Message`, `Result`), поэтому
`en.md` добавляется без изменений кода. Третий язык — одна запись в `headings.ts`.

## Ограничения

- Пределы 64 КБ, 2000 разделителей, 16 уровней вложенности, 100 ошибок — без замеров на
  настоящих уроках, кроме B1 (около 9 КБ, около 60 разделителей).
- Подпись зоны не может содержать двоеточие перед списком участников; имя участника — без `*`.
- Набор иконок не сверяется с `content/icons` (иконок ещё нет, M1.2): проверяется только вид
  имени.
- Номера CWE и CVE проверяются по виду, не по NVD и MITRE (сверка фактов — верификатор, L5).
- `parseLesson` получает уже разобранное дерево; модуль тянет `mdast-util-from-markdown`, поэтому
  в браузерную сборку его не импортируют — данные собирает сборка (M1.1b).
