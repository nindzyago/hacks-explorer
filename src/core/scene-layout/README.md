# src/core/scene-layout — раскладка сцены

Слой L0: чистые функции без DOM. Где стоит каждый участник, где рамка зоны и подпись, где линия
сообщений — по данным урока и ширине сцены (дизайн M1.2 E1, K19, K45); какой шаг текущий и где
его сообщение в данный момент часов плеера (E2, E8, D3 a). Рисует сцена `src/scene`.

## API

```ts
import { layoutScene } from './layout';
import { currentStep, layoutMessage, stepsInMode, travelProgress, TRAVEL_MS } from './message';
import { describeScene, describeStep, sceneTitle } from './describe';

const layout = layoutScene({ participants, zones, width: 390 });
layout.participants[0]; // { id, cx, icon: Rect, name: TextBlock, note: TextBlock | null, area, span }
layout.zones[0]; // { id, danger, members, rect, label: TextBlock }
layout.lane; // { x1, x2, y } — линия, по которой едет сообщение

const current = currentStep(lesson.steps, defence, 3); // { number, count, step } | null
const message = layoutMessage(layout, current.step, clockMs - startedMs, reducedMotion);
// { kind, stopped, sign, word, wordY, wordFit, x, y, progress, arrived, trail, ring, plaque,
//   token, body, wordBox } | null

describeScene({ participants, zones }); // участники и зоны для экранных читалок
describeStep(participants, current); // «Шаг 3 из 5. Заголовок: кто → кому, вредное сообщение «…».»
```

Единицы — CSS-пиксели: сцена рисует SVG с `viewBox` ровно `width × height`, поэтому 11 в
раскладке — 11 px на экране.

## Правила раскладки

- Участники в одну линию в порядке списка, на равных расстояниях: колонка `(width − 8) / n` (M1.2c: поля сцены 4 px).
- Зона — прямоугольник от первого до последнего своего участника, на `min(85, колонка/2 − 3)`
  в стороны от центров (85 — как в прототипе), поэтому между зонами соседних колонок не меньше
  6 px (M1.2c: было 8 — на телефоне колонке нужны эти 2 px). Участник без зоны просто стоит в своей колонке. Зона без известных участников не рисуется.
  Вложенные и пересекающиеся зоны сюда не доходят: их отклоняют проверка урока и чтение данных
  сайтом (`src/core/lesson/site-read.ts`, M1.2b).
- Все зоны одной высоты: от верха сцены до низа самой длинной подписи участника.
- Подпись зоны: JetBrains Mono 11 px, интервал 1 px, в левом верхнем углу рамки.
- Линия сообщений проходит на 38 px ниже подписей зон (место для слова над сообщением, M1.2b) и
  над иконками, от первого участника до последнего.
- Иконка: не шире 150 px и не шире зоны участника без 16 px, пропорции листа 310 × 275.
- Имя: Onest 700, 13 px в широкой колонке (от 140 px), 12 в узкой, 11 — если иначе не влезает
  самое длинное слово. Заметка: JetBrains Mono 11 px. Меньше 11 px текста нет.
- Текст имени и заметки занимает рамку колонки без 4,5 px с каждой стороны (M1.2c): там идут
  линия рамки зоны (0,75 px внутрь) и кольцо получателя. `area` — середина линии кольца, 2,5 px
  внутри рамки колонки, толщина `RING_STROKE` = 2: линия занимает 1,5…3,5 px и не задевает ни
  рамку зоны, ни текст, ни иконку. `span` — края рамки колонки.
- Перенос строк только по пробелам (M1.2b): адрес и слово внутри не рвутся. Слово чуть шире
  строки рисуется уже — до 85% ширины (`fit` у строки, в SVG `textLength`), шрифт остаётся
  11 px; ещё шире — сокращается с «…»: у адреса пропадает середина, конец после первой точки
  остаётся (`bank-…example`), у другого слова — конец. Больше трёх строк — третья кончается «…».
- Ширина вне 280…1600 (и `NaN`) приводится к границе; при меньшем окне сцена масштабируется
  целиком.

## Сообщение (M1.2b)

- Шаги режима: общие (`both`) и шаги режима (`without-defence` или `with-defence`) в порядке
  урока (K20). Номер с 1; меньше 1 или не число — первый шаг, за концом — последний, дробь
  отбрасывается. Шагов в режиме нет — `null`, сцена пишет «В этом режиме у урока нет шагов».
- Путь: от центра колонки отправителя к центру колонки получателя по линии сообщений за
  `TRAVEL_MS` = 900 мс часов плеера, с плавным разгоном и торможением (как в прототипе):
  ровно середина пути в середине шага. Время до начала шага — начало пути, после — конец.
  `reducedMotion` — сразу у цели (S11). Шаг от участника к самому себе не движется и не
  оставляет следа.
- Место сообщения у участника (M1.2c) — рамка его зоны без 2 px с каждой стороны (у участника
  без зоны — рамка его колонки), в пределах сцены. Плашка, жетон и слово на весь шаг одного
  размера — того, что помещается в меньшее из мест отправителя и получателя; в начале и в конце
  пути сообщение стоит над колонкой участника, сдвинутое ровно настолько, чтобы остаться в его
  месте. Поэтому на покое сообщение не задевает чужих рамок, подписей и иконок (кроме иконок
  отправителя и получателя: жетон и двухстрочная плашка ложатся на их верх).
- Плашка — моно 11 px жирный. Широкая (как в прототипе): одна строка, 24 px, знак в 16 px слева,
  поля 9 px. Если с тенью (3 px) она не помещается — компактная: поля 4 px, знак в 11…16 px, текст
  до двух строк (30 px высотой) с переносом по пробелам; строка чуть шире места рисуется уже, до
  85% (`textLength`), дальше «…». Шаг с `icon:имя` — круглый жетон радиусом 21 px с иконкой
  вместо плашки, знак на значке в углу.
- Слово над сообщением (интервал 0,5 px) рисуется уже, если шире места без 6 px, но не меньше
  85%. `body` и `wordBox` — что занимают плашка или жетон (с тенью и значком) и слово.
- Цвет вида всегда продублирован знаком и словом над сообщением: вредное — «!», «вредное»;
  безопасное — «✓», «безопасное»; обычное — стрелка в сторону движения (точка, если не
  движется), «обычное». Остановленное защитой (`stopped`) едет как сообщение своего вида и там,
  где остановилось (у получателя шага), получает щит и слово «остановлено»; дальше по линии
  ничего не едет (D3 a, K44).
- Кольцо — `area` получателя; след — от точки, где сообщение стояло в начале пути, до
  сообщения, пока оно в пути и после (M1.2c: раньше — от центра колонки).

## Ограничения

- Ширина текста оценивается (0,6 em на символ: ровно JetBrains Mono, с запасом для Onest), а не
  меряется. Настоящие рамки текста в браузере проверяет `e2e/scene.spec.ts` на 1280 и 390 px.
- Порядок участников в зоне не проверяется здесь: правило соседства держат проверка урока и
  чтение данных.
- В пути сообщение пересекает рамки зон — оно едет между ними. Наложения проверяются только на
  покое, в начале и в конце шага (`message.test.ts`, `e2e/scene.spec.ts`).
- «Кто остановил» в данных урока нет: остановленное сообщение стоит у получателя шага, поэтому
  `stopped` ставится на шаг, где вредное сообщение доходит до защитника (B1: `param`, сервер →
  база; I1: `leak`, атакующий → банк, и `autofill` у самого сотрудника).
- Место считается для B1 и I1 на 356…926 px. На очень тесной сцене (шесть участников на 280 px,
  колонка около 45 px) слово не сжимается сильнее 85% и может выйти из места на соседнюю рамку;
  такой урок на телефоне пока не показывается.
