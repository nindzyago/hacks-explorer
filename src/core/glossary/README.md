# src/core/glossary — словарь терминов

Слой L0 (M2.4, K7). Словарь — один Markdown-файл на язык: `content/locales/<язык>/glossary.md`
(рядом с `ui.md` из M2.3). Модуль проверяет его, находит термины в тексте уроков при сборке и
даёт сайту данные. Сайт текст не ищет (K31): он получает готовые узлы `term`.

| Файл | Что делает | Тянет разборщик Markdown |
|---|---|---|
| `check.ts` | `checkGlossaries`: файлы словаря → данные или ошибки с файлом и строкой | да (только сборка) |
| `match.ts` | правило поиска: `createMatcher`, `linkTerms` | нет |
| `build.ts` | словарь → файл сайта; урок → урок со ссылками на термины | нет |
| `site.ts` | `SiteGlossary`, `glossaryFile`, `readSiteGlossary` (враждебный ввод) | нет |
| `words.ts` | слова файла на каждом языке: `Словарь`, `Разделы`, `Формы` | нет |

## Формат на примере

````markdown
# Словарь

`glossary` ru · `format` 1

## Разделы

- `web` Веб и базы данных
- `basics` Основы

## `sql-injection` SQL-инъекция

`category` web · `see` injection, parameterized-query · `lessons` B1

Формы: SQL-инъекция, SQL-инъекции, SQL-инъекцию, SQL-инъекцией, SQL-инъекций

Инъекция в запрос к базе данных: сервер вклеивает присланный текст в SQL-запрос…

## `attacker` Атакующий

`category` basics · `see` victim · `lessons` B1, I1

Тот, кто пытается заставить систему работать не по правилам…
````

| Часть | Как пишется | Обязательно |
|---|---|---|
| Заголовок | `# Словарь` (на языке файла) | да |
| Строка словаря | `` `glossary` ru · `format` 1 ``, язык равен имени папки | да |
| Разделы | `## Разделы`, список `` - `id` Подпись `` | да, сразу после строки словаря |
| Термин | `## `id` Название` — id из строчных латинских букв, цифр и дефиса | — |
| Служебная строка | `` `category` id `` обязательно; `` `see` id, id `` и `` `lessons` B1, I1 `` по желанию | да |
| Формы | `Формы: форма, форма, …` — слова, как они стоят в тексте; без строки термин в тексте не ищется (его открывают схема и «см. также») | нет |
| Определение | абзацы и списки, **жирный**, *курсив*, `код` — как текст урока; до 700 знаков | да |

Ссылок, HTML и картинок нет нигде в файле. Адреса и домены — только учебные (L4.2), как в уроках.

### Проверка (`npm run content`, сборка, gate)

Ошибка — данные `{ file, line, column, path, code, message }`, как у уроков (общий `report.ts`):

| code | когда |
|---|---|
| `bad-path`, `unknown-language` | файл не `content/locales/<язык>/glossary.md`; языка нет в `words.ts` |
| `too-large`, `too-complex`, `too-deep` | пределы файла урока (64 КБ, 1000 строк…); больше 300 терминов, 20 разделов, 40 форм у термина, 60 знаков в форме или названии, 700 в определении |
| `missing-title`, `bad-header`, `missing-section` | нет `# Словарь`, строки словаря или `## Разделы` |
| `bad-line`, `unknown-word`, `bad-value` | служебная строка не того вида; неизвестное слово; неверный id; раздел не из списка; форма — не слова (`запрос.*`, `[аы]`, `|`) |
| `duplicate` | термин, раздел, форма, `see` или урок повторяются; форма у двух терминов |
| `unknown-term` | `see` называет термин, которого нет; `term:` участника или зоны урока — тоже (ошибка в файле урока) |
| `unknown-lesson` | `lessons` называет урок, которого нет в `content/lessons` |
| `html`, `image`, `link`, `not-allowed`, `empty-section` | запрещённое в тексте; NUL и невидимые знаки направления текста (U+202A–U+202E, U+2066–U+2069) в любом месте файла; термин без определения |
| `address` | IP или домен вне учебных (правило уроков, с M2.8 и IPv4 числом) |
| `unknown-id` | CWE, техника ATT&CK, пункт OWASP или CVE в тексте не из проверенных списков `src/core/lesson/ids.ts` (M2.8, K86) |
| `missing-glossary` | у языка уроков нет словаря (K94); русский нужен всегда, когда есть уроки |
| `translation-mismatch` | перевод расходится с русским: разделы, id терминов по порядку, `category`, `see`, `lessons` |

## Правило поиска терминов (`match.ts`)

Сборка (`scripts/lesson-data.ts`) ищет термины в трёх уровнях каждого шага и в «Как защититься»,
сайт получает `{ type: 'term', id, children }`:

1. Ищутся только формы из строки «Формы», никаких шаблонов. Русские падежи перечисляются.
2. Регистр не важен, «ё» равна «е». Пробел в форме совпадает с одним пробелом или переносом
   строки.
3. Только целые слова: вокруг формы нет букв, цифр, `_` и `-`. Поэтому `SQL` не находится в
   `SQL-инъекция` и `SQL-запрос` — такие слова пишутся отдельными формами.
4. Где начинаются формы нескольких терминов, побеждает самая длинная; найденный текст
   пропускается целиком, внутри него короче не ищется.
5. Один термин — одна ссылка на блок (абзац или весь список), на первом вхождении.
6. Код не ищется: ни `код в строке`, ни блоки кода. Внутри **жирного** и *курсива* ищется, через
   их край — нет; знаки сразу за краем считаются для целых слов: в `**SQL**-инъекция` слово `SQL`
   не находится.
7. В определении термин не ссылается сам на себя; на другие термины ссылается.

## Данные сайта

`data/glossary/<язык>.json` (`SiteGlossary`): разделы, термины с определением (дерево узлов со
ссылками), `see` и уроками `{ id, title }` (название на языке словаря). Форм в файле нет. Файл
больше 30 КБ — ошибка сборки и `npm run budget`. Имя без хеша: файл загружается при первом
открытом термине (`src/services/glossary`), не при открытии страницы.

## Ограничения

- Формы перечисляются руками: незнакомая форма слова не найдётся (это выбор, а не ошибка:
  лишняя ссылка хуже пропущенной).
- Термин через край жирного (`**база** данных`) не находится.
- Одно слово — один термин: «запрос» значит и HTTP-запрос, и запрос к базе, поэтому
  определение общее.
- Последовательность «больше 300 терминов» проверяется до разбора каждого; 64 КБ файла хватает
  примерно на 120–150 терминов с короткими определениями.
