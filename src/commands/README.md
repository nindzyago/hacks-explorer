# src/commands — реестр команд

Слой L2: может импортировать `src/core` и `src/services`, ничего не знает о Svelte и DOM.
Всё, что делает пользователь, — команда; интерфейс, клавиатура, тесты и канал управления
вызывают её по id (архитектура §3, решение K12).

## API

```ts
import { createRegistry } from './registry';

const registry = createRegistry<AppState>(() => appState); // откуда брать состояние для enabled

registry.register({
  id: 'player.goto', // область.действие
  titleKey: 'command.player.goto', // ключ строки в content/locales/<язык>/ui.md (тест: каждый titleKey есть, M2.3)
  params: { step: { kind: 'integer', min: 0, max: 99 } },
  enabled: (state) => state.lessonOpen, // нет поля — команда доступна всегда
  run: ({ step }) => {
    /* step: number, уже проверен */
  },
});

registry.run('player.goto', { step: 3 }); // { ok: true } | { ok: false, error }
registry.list(); // [{ id, titleKey, params, enabled }]
```

Виды параметров (`params.ts`): `string` (`maxLength`, по умолчанию 200; `pattern` — текст
регулярного выражения, которому должно соответствовать всё значение, M1.3), `integer` и `number`
(`min`, `max`; `values` — список допустимых чисел, M1.3), `boolean`, `enum` (`values`). У любого может быть `optional: true`. Описание —
простые данные, `list()` отдаёт его как есть, оно переживает JSON.

## Поведение

- `run(id, params)` никогда не бросает исключение. Ошибка — простые данные
  `{ code, commandId, message, problems? }`:

  | code | когда |
  |---|---|
  | `unknown-command` | такого id нет; id не строка |
  | `invalid-params` | параметры не подошли; `problems` — список `{ param, problem }` |
  | `disabled` | `enabled(state)` вернула `false` |
  | `failed` | `run` или `enabled` команды бросили что угодно, в том числе значение, которое нельзя напечатать (`unprintable error`) |

- Порядок проверок: id, параметры, `enabled`, запуск. Плохой вызов виден в любом состоянии.
- Параметры враждебны (L0.2). Ничего не приводится: `"3"` — не число, `"true"` — не boolean.
  Лишний параметр — ошибка. Принимается только простой объект (или `undefined` вместо пустого);
  каждое значение читается один раз, команда получает новый объект только с описанными полями.
  Отсутствующий необязательный параметр — `undefined`. У этого объекта нет прототипа, поэтому
  параметр может называться `constructor` или `toString`, а `params.toString()` вызвать нельзя.
- `register` бросает `CommandDefinitionError` с `code`: `duplicate-id` или `invalid-definition`
  (id не вида `область.действие`, пустой `titleKey`, плохое описание параметров). Это ошибка в
  коде команды: её ловят тесты и gate, читатель её не видит. Первая команда с этим id остаётся.
- `register` замораживает переданное описание параметров.
- `list()` — команды в порядке регистрации; если `enabled` бросает или возвращает не `true`,
  в списке `enabled: false`.

## Приложение (`app.ts`)

`createApp()` → `{ store, registry }`: одно хранилище состояния (`src/core/store.ts`, состояние
`AppState` из `src/core/state.ts`) и один реестр со всеми командами. `src/main.ts` создаёт его
один раз и отдаёт интерфейсу (свойство `app` у `App.svelte`) и каналу управления
(`src/control`). Тесты создают своё приложение на каждый тест.

Новая группа команд — свой файл `src/commands/<область>.ts` с функцией
`register<Область>Commands(registry, store)` и одна строка в `createApp()`. Команда меняет
состояние так: `store.set(Object.freeze({ ...store.get(), поле }))`. Состояние — замороженные
простые данные, которые переживают JSON: его целиком отдаёт канал управления.

| Команда | Параметры | Что делает |
|---|---|---|
| `theme.set` | `theme`: `light` или `dark` | меняет `state.theme`; интерфейс ставит `data-theme` на корень страницы. Выбор пока не запоминается между визитами (M2.6) |
| `locale.set` | `lang`: язык сайта из `content/locales/languages.md` (`createApp({ languages })`, по умолчанию только `ru`) | меняет `state.locale` — язык интерфейса, урока, словаря и адреса (M2.3, S5); урок, шаг, режим, глубина и скорость остаются. Другой язык, регистр, не строка — `invalid-params`. Вызывают переключатель «RU / EN» (только когда языков больше одного), адрес и канал управления; выбор после открытия страницы запоминается в `localStorage` (`src/main.ts`) |
| `view.set` | `view`: `scene` или `sequence` | меняет `state.view` — вид урока (M6.2, K130). По умолчанию `scene`; смена шага, режима, урока и языка его не меняет; в адресе его нет |
| `depth.set` | `depth`: `simple`, `steps` или `deep` | меняет `state.depth` — глубину панели объяснения (M1.4, S3). По умолчанию `simple`; смена шага, режима и урока её не меняет |
| `glossary.open` | `id`: id термина словаря (`[a-z][a-z0-9-]{0,31}`) | меняет `state.glossary`: определение термина открывается на месте (M2.4, K7), одно за раз; другой id заменяет открытое. Есть ли такой термин, решает окно определения (говорит «Такого слова в словаре нет»). Текст, схема, «см. также» и канал управления вызывают эту команду |
| `glossary.close` | — | `state.glossary` = null |
| `player.play` | нет | пуск: сообщение в пути доезжает (и на последнем шаге: тогда после прибытия пуск выключается), доехавшее — сразу следующий шаг, после доехавшего последнего — с первого. Повтор при пуске ничего не меняет. Пока у урока нет шагов (не загружен, ошибка загрузки) — `disabled` |
| `player.pause` | нет | пауза; сообщение в пути доезжает |
| `player.step` | нет | следующий шаг с текущего времени часов, пуск выключается; на последнем шаге ничего не меняет |
| `player.back` | нет | предыдущий шаг с текущего времени, пуск выключается; на первом ничего не меняет. Три шага и назад дают ровно прежнее состояние (S1) |
| `player.goto` | `step`: целое 1…100 | шаг в текущем режиме с текущего времени, пуск выключается; номер за концом урока — последний шаг; повтор того же шага запускает его заново. «Сначала» = `{ step: 1 }` |
| `player.speed` | `value`: 0.5, 1 или 2 | скорость хода и пауз; сообщение не прыгает, пуск продолжается. Другое значение — `invalid-params` (`values` в описании параметра) |
| `defence.toggle` | нет | режим «С защитой» наоборот: номер шага сохраняется (S2, обрезается по новому режиму), шаг заново, пуск выключается |
| `defence.set` | `on`: boolean | то же с заданным режимом (сверх архитектуры §3: тестам и адресам M2.2) |
| `lesson.open` | `id`: строка до 32 знаков вида `B1` | урок на странице (M1: одна страница, адреса — M2.2): `state.lesson = id`, шаг 1 без защиты с текущего времени, пауза, скорость прежняя. Число шагов неизвестно до загрузки (тот же урок — сохраняется). Id не того вида (`[A-Z][0-9]{1,3}`, проверяет описание параметра) — `invalid-params`; урока нет в каталоге — страница показывает «Такого урока нет…» |

`player.*`, `defence.*` и `lesson.open` — в `player.ts`,
`registerPlayerCommands(registry, store, clock, { onTimeNeeded })`; правила — чистая модель
`src/core/player`. Временные `scene.step` и `scene.defence` (M1.2) удалены. Автопроигрывание —
подписчик часов плеера: каждый шаг часов может закончить шаг урока, таймеров нет.
`onTimeNeeded(needed)` зовётся, когда плееру стало или перестало быть нужно время (пуск или
сообщение в пути): `src/main.ts` включает и выключает здесь драйвер реального времени. Число
шагов загруженного урока интерфейс передаёт через `app.lessonLoaded(id, counts)` — это данные
загрузки, не действие, поэтому не команда; для не открытого урока вызов ничего не делает.

## Ограничения

- Команды синхронные. Долгая работа (подгрузка урока) запускается командой и отражается в
  состоянии; результат `run` говорит только, что команда принята и отработала без исключения.
- Команду нельзя снять с регистрации или заменить.
- В сообщениях id обрезается до 64 знаков, имя лишнего параметра до 40, проблем не больше 20
  (дальше строка «and N more»), текст исключения до 200 знаков.
- Сообщения об ошибках на английском и предназначены разработчику и каналу управления;
  читателю их показывает интерфейс своими словами по `code`.
- Целые числа — только в безопасном диапазоне JavaScript (±2^53).

## Команды часов (`clock.ts`)

`registerClockCommands(registry, clock, { onManual })` регистрирует `clock.set { ms }` и
`clock.tick { ms }` (архитектура §4). `ms` — целое от 0 до 86 400 000 для `set` и до
`clock.maxTickMs` (10 000) для `tick`; всё остальное отсекает реестр как `invalid-params`.
Перед каждым ручным сдвигом вызывается `onManual` — туда передаётся `stop` драйвера реального
времени, чтобы системное время не подмешивалось в сценарий. Отказ самих часов (например, время
вышло за 24 часа) приходит как `failed` с кодом часов в начале `message`.

`createClockChannel(registry)` возвращает `{ set(ms), tick(ms) }` — готовую часть `clock` для
`window.__app`; обе функции вызывают команды по id и возвращают тот же `RunResult`.
