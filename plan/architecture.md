# Архитектура

Статический сайт: Vite + Svelte 5 + TypeScript. Всё собирается в файлы, сервера нет.
Выкладка на Cloudflare, выпуски по тегу версии на GitHub (K10).

## 1. Слои

| Слой | Модули | Может зависеть от |
|---|---|---|
| L0 ядро | `src/core/lesson` (типы и схема урока), `src/core/player` (машина шагов), `src/core/cvss` | ни от чего внутри проекта |
| L1 сервисы | `src/services/catalog`, `i18n`, `glossary`, `router` | L0 |
| L2 команды | `src/commands` (реестр и все действия) | L0–L1 |
| L3 адаптеры | `src/ui` (Svelte), `src/scene` (SVG), `src/control` (`window.__app`) | L0–L2 |
| Контент | `content/lessons/<id>/lesson.yaml`, `content/locales/<язык>/<id>.yaml`, `content/locales/<язык>/glossary.yaml`, `content/icons/` | ни от чего: это данные |

Проверяется в gate через dependency-cruiser. Контент не импортирует код, код не знает
конкретных уроков: он читает каталог, собранный при сборке.

## 2. Модель данных

Урок — данные, не код.

- `Lesson`: id, раздел, волна, паспорт (CWE, OWASP, CVE, вектор CVSS, источники),
  `scene` (узлы, зоны доверия, связи), `steps[]`, `defence` (какие шаги и как меняются
  при включённой защите), `sandbox?` (зарезервировано, пусто в первой версии).
- `Step`: откуда, куда, вид сообщения (обычное, вредное, остановлено), ключи текста
  для трёх уровней глубины, что подсветить в инспекторе.
- Тексты лежат отдельно по языкам: `content/locales/ru/B1.yaml`. Новый язык — новая папка.
- Урок и переводы — YAML (K10). Сборка читает их, проверяет по схеме и превращает в данные
  сайта; текст урока выводится как текст, не как HTML.
- Узлы сцены берутся из одного набора иконок (`content/icons`, стиль K5); урок ссылается на
  иконку по имени:
  атакующий, пользователь, браузер, сайт, база, почта, роутер, DNS, облако и так далее.

Все адреса в уроках только учебные: 192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24,
2001:db8::/32, домены example.com, example.org, *.example, *.test.

## 3. Команды

Реестр в `src/commands/registry.ts`, имена `область.действие`:
`lesson.open`, `player.play`, `player.pause`, `player.step`, `player.back`, `player.goto`,
`player.speed`, `defence.toggle`, `depth.set`, `locale.set`, `theme.set`, `catalog.filter`,
`glossary.open`. Интерфейс, клавиатура, тесты и канал управления вызывают команды по id.

## 4. Канал управления

Браузер под Playwright. В dev-сборке и в тестах есть `window.__app`:
`commands.list()`, `commands.run(id, params)`, `state.get()`, `clock.set(ms)`, `clock.tick(ms)`.
У каждого интерактивного элемента стабильный `data-testid`. Снимки делает Playwright.

## 5. Хранение

Сервера и учётных записей нет. В `localStorage` только тема, язык и скорость. Положение
в уроке хранится в адресе: `/ru/lesson/B1#step-3-defence`.

## 6. Бюджеты

| Сценарий | Бюджет | Чем измеряется |
|---|---|---|
| Первая загрузка главной | не больше 150 КБ JS в gzip | проверка размера сборки в gate |
| Открытие урока | урок подгружается отдельным файлом не больше 30 КБ | проверка размера сборки |
| Анимация шага | 60 кадров в секунду на телефоне среднего класса | замер в Playwright, оценка |
