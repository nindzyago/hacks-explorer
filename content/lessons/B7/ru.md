## Шаги

### `order` Заказ в XML

`attacker → server` · `legit`
Сообщение: XML-заказ · Итог: «Товар 17 добавлен»

```xml
<order>
  <item>17</item>
</order>
```

#### Просто

Оптовый склад принимает заказы от магазинов-партнёров в виде **документов XML**. Атакующий
зарегистрировался как партнёр и отправляет обычный заказ: товар номер 17.

#### По шагам

Сервер разбирает документ программой-парсером, находит номер товара и отвечает: «Товар 17
добавлен». В ответе он повторяет то, что прочитал из документа.

#### Глубже

XML — старый и очень распространённый формат: на нём работают SOAP-сервисы, файлы Office, SVG,
многие интеграции между компаниями. Парсеры XML умеют гораздо больше, чем нужно для заказа, и
часть этих умений включена по умолчанию.

### `doctype` Документ с сущностью

`attacker → server` · `attack`
Сообщение: XML с DOCTYPE и сущностью · Итог: принят на разбор

```xml
<!DOCTYPE order [
  ⟦<!ENTITY x SYSTEM "file:///etc/passwd">⟧
]>
<order><item>&x;</item></order>
```

#### Просто

Атакующий добавляет в начало документа **объявление**: «словом `x` назови содержимое файла
`/etc/passwd`». А в номер товара пишет `&x;` — «вставь сюда `x`».

#### По шагам

Строка `DOCTYPE` открывает описание документа (DTD). В нём объявлена сущность `x` — именованная
подстановка. Слово `SYSTEM` значит, что её содержимое лежит снаружи, по адресу после него. Здесь
адрес — файл на диске сервера.

#### Глубже

Внешние сущности описаны в самом стандарте XML 1.0 (раздел 4.2.2): содержимое берётся по
системному идентификатору, адресу URI. OWASP пишет, что вместо файла может стоять и адрес `http`
во внутренней сети: тогда сервер сам сходит туда, куда атакующему не дотянуться.

### `resolve` Парсер читает файл

`server → files` · `attack` · `without-defence`
Сообщение: прочитать /etc/passwd · Итог: атака

```text
&x;  →  ⟦file:///etc/passwd⟧
```

#### Просто

Парсер послушно **открывает файл** с диска сервера и ставит его содержимое на место `&x;`. Он
делает это до того, как программа заказов вообще увидит документ.

#### По шагам

Парсер читает файл с правами программы склада. Всё, что программе можно прочитать, можно и
подставить: настройки, ключи, исходный код.

#### Глубже

Это ошибка CWE-611: программа разбирает документ XML, сущности которого ведут к ресурсам за
пределами того, что ей положено трогать. В OWASP Top 10:2021 этот класс входит в пункт A05
Security Misconfiguration: опасна именно настройка парсера, а не код заказов.

### `echo` Файл в ответе

`server → attacker` · `attack` · `without-defence`
Сообщение: «Товар root:x:0:0... не найден» · Итог: файл у атакующего

```text
Товар «⟦root:x:0:0:root:/root:/bin/sh ...⟧» не найден
```

#### Просто

Номер товара теперь — **весь файл**. Сервер не находит такой товар и честно повторяет в ошибке,
что прочитал. Атакующий получил файл сервера.

#### По шагам

`/etc/passwd` в Linux — список учётных записей системы. Он не секретный, но показывает, что
атака работает. Следующими атакующий попросит файлы с паролями к базе или ключами.

#### Глубже

Атака работает и без такого удобного ответа. OWASP отмечает, что приложению не обязательно
возвращать файл: данные можно вывести наружу запросом к серверу атакующего, например через имена
в DNS. Такой вариант называют слепым XXE. А сущность, которая указывает на ресурс без конца,
может занять парсер надолго — это отказ в обслуживании.

### `reject` DOCTYPE запрещён

`server → server` · `attack` · `with-defence` · `stopped`
Сообщение: документ с DOCTYPE · Итог: отклонён, атака не сработала

```text
парсер: DOCTYPE не принимается → ⟦<!DOCTYPE order [...]>⟧ отклонён
```

#### Просто

В режиме защиты парсер настроен **не принимать описание документа** вообще. Заказу DTD не нужен.
Документ с `DOCTYPE` отклоняется целиком, файл никто не читает. Атака останавливается здесь.

#### По шагам

Парсер видит строку `DOCTYPE` в начале и сразу останавливает разбор с ошибкой. До сущности `x`
и до диска дело не доходит.

#### Глубже

Это первый совет OWASP: по возможности отключить DTD и отклонять `DOCTYPE`. Если DTD всё же
нужны — запретить внешние сущности и загрузку внешних DTD и ограничить раскрытие сущностей.
Настройки у каждого парсера свои. Например, в Java для этого у фабрики парсера включают признак
`disallow-doctype-decl`, а библиотека libxml2 начиная с версии 2.9 по умолчанию не подставляет
сущности.

### `refuse` Ошибка разбора

`server → attacker` · `safe` · `with-defence`
Сообщение: 400 DOCTYPE запрещён · Итог: атака не удалась

```http
HTTP/1.1 400 Bad Request
```

#### Просто

Атакующий получает короткий отказ. В ответе нет ни строчки из файлов сервера.

#### По шагам

Обычные заказы без `DOCTYPE` проходят как раньше: партнёрам ничего менять не нужно.

#### Глубже

OWASP советует считать отказ от защитной настройки ошибкой: если парсер не поддерживает нужный
запрет, не разбирать чужой XML с частичной защитой. И не забывать про XInclude, схемы и таблицы
стилей XSLT: они тоже умеют подгружать внешние ресурсы.

## Как защититься

- **Без DTD.** Настройте парсер отклонять `DOCTYPE`, если формату данных не нужно описание
  документа. Чаще всего не нужно.
- **Без внешних сущностей.** Если DTD нужны, запретите внешние сущности и загрузку внешних DTD,
  ограничьте раскрытие сущностей.
- **Каждый парсер — отдельно.** Настройки и значения по умолчанию у библиотек разные; проверьте
  все места, где разбирается XML, включая схемы, XInclude и XSLT.
- **Обновления.** Держите библиотеки XML свежими: в новых версиях опасное часто выключено по
  умолчанию.
- **Если можно — проще формат.** Где XML не обязателен, простые данные удобнее передавать в JSON.
