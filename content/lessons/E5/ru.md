## Шаги

### `patch` Настройки с особым ключом

`attacker → server` · `attack`
Сообщение: PATCH /api/settings · Итог: принят

```http
PATCH /api/settings
Content-Type: application/json

{"theme": "dark", ⟦"__proto__": {"isAdmin": true}⟧}
```

#### Просто

На сайте можно сменить тему оформления. Атакующий отправляет настройки, где рядом с темой лежит
поле со странным именем `__proto__`, а внутри — `isAdmin: true`, «я администратор».

#### По шагам

Сервер написан на JavaScript. `JSON.parse` превращает текст запроса в объект; `__proto__` в нём —
пока обычное поле с вложенным объектом. Опасным оно станет на следующем шаге.

#### Глубже

В JavaScript у объекта есть **прототип** — другой объект, у которого он «наследует» свойства:
если поля у самого объекта нет, язык ищет его в прототипе. У почти всех обычных объектов прототип
один и тот же, `Object.prototype`. А `__proto__` — особое имя: присваивание в него меняет
прототип, а чтение отдаёт прототип.

### `merge` Слияние пишет в общий прототип

`server → server` · `attack` · `without-defence`
Сообщение: merge(настройки, запрос) · Итог: Object.prototype.isAdmin = true

```js
function merge(target, source) {
  for (const key in source) {
    if (typeof source[key] === 'object') merge(target[key], source[key]);
    else target[key] = source[key];
  }
}
// ⟦target['__proto__'] → Object.prototype⟧
```

#### Просто

Сервер **сливает** присланные настройки с сохранёнными: проходит по всем полям и копирует их.
Дойдя до `__proto__`, функция идёт не в поле, а **в общий прототип всех объектов** — и записывает
туда `isAdmin: true`.

#### По шагам

`target['__proto__']` возвращает не вложенный объект настроек, а `Object.prototype`. Функция
вызывает себя для него и копирует `isAdmin` уже туда. Теперь у **каждого** обычного объекта в
программе есть унаследованное свойство `isAdmin` со значением `true`.

#### Глубже

MDN делит атаку на две фазы: загрязнение (этот шаг) и использование (следующие). К прототипу
ведут и другие пути: пара ключей `constructor` и `prototype`, запись по пути из точек вроде
`a.b.c`. MITRE в CWE-1321 приводит примеры из настоящих библиотек: рекурсивное слияние, задание
значений по умолчанию, запись по пути.

### `admin` Проверка прав находит чужое свойство

`attacker → server` · `attack` · `without-defence`
Сообщение: GET /admin · Итог: user.isAdmin = true

```js
const user = await db.findUser(session.userId); // { name: 'mallory' }
if (⟦user.isAdmin⟧) showAdminPanel();
```

#### Просто

Атакующий открывает страницу администратора. Сервер проверяет: «у этого пользователя есть
`isAdmin`?» У самого объекта поля нет, но язык находит его **в прототипе** — и пускает.

#### По шагам

Объект пользователя из базы `users` содержит только имя. Поиск `isAdmin` идёт по цепочке
прототипов, доходит до `Object.prototype` и находит там `true`. Проверка проходит.

#### Глубже

MDN приводит ровно такой случай: если у обычных пользователей нет поля `isAdmin`, после
загрязнения администраторами считаются **все**. Загрязнение живёт в памяти процесса до
перезапуска, поэтому затрагивает запросы всех посетителей, а не только атакующего.

### `panel` Панель администратора открыта

`server → attacker` · `attack` · `without-defence`
Сообщение: страница /admin · Итог: доступ получен

```text
200 OK — Панель администратора
```

#### Просто

Атакующий в панели администратора, хотя никто не давал ему этих прав. Он не взламывал пароль и не
трогал базу — он поменял поведение **всех объектов** программы одним полем.

#### По шагам

Сервер отдаёт панель, потому что проверка прав сказала «да». Ошибки в самой проверке нет: она
просто не ожидала унаследованного поля.

#### Глубже

Что именно сделает загрязнение, зависит от кода, который потом прочтёт свойство. MITRE называет
подмену данных приложения и падение программы. MDN показывает подмену параметров запроса `fetch`
и путь к XSS в браузере: опасная цель — свойство `srcdoc` у `iframe`, которое задаёт содержимое
фрейма; подменённое через прототип, оно может принести на страницу чужой скрипт.

### `filter` Опасные ключи отброшены

`server → server` · `attack` · `with-defence` · `stopped`
Сообщение: опасный ключ · Итог: отброшен, атака не сработала

```js
const FORBIDDEN = new Set(['__proto__', 'constructor', 'prototype']);
for (const key of Object.keys(source)) {
  if (FORBIDDEN.has(key)) continue; // ⟦__proto__⟧ пропущен
  // …
}
```

#### Просто

Теперь слияние пропускает три опасных имени: `__proto__`, `constructor` и `prototype`. До
прототипа ему не добраться. Здесь атака и останавливается.

#### По шагам

Функция перебирает только собственные ключи присланного объекта и пропускает запрещённые. Тема
`dark` сохраняется, `__proto__` отбрасывается, `Object.prototype` остаётся чистым.

#### Глубже

MITRE советует отвергать имена, ведущие к прототипу. Ещё надёжнее проверять запрос по схеме,
где перечислены разрешённые поля: тогда лишние поля отвергаются целиком. Вторым слоем MDN и OWASP
называют `Object.freeze(Object.prototype)`, объекты без прототипа `Object.create(null)` и `Map`
вместо обычных объектов для данных от посетителя.

### `admin-try` Попытка открыть панель

`attacker → server` · `attack` · `with-defence`
Сообщение: GET /admin · Итог: user.isAdmin не найден

```js
if (Object.hasOwn(user, 'isAdmin') && user.isAdmin === true) showAdminPanel();
```

#### Просто

Атакующий всё равно пробует открыть панель администратора. Но прототип чистый, поля `isAdmin` у
него нет.

#### По шагам

Проверка спрашивает только **собственное** поле объекта, через `Object.hasOwn`. Даже если
прототип где-то загрязнят, унаследованное значение такую проверку не пройдёт.

#### Глубже

MDN советует для важных проверок `Object.hasOwn` и явные значения по умолчанию: такой код не
зависит от того, что лежит в прототипе. Это не замена фильтру ключей, а ещё один слой.

### `denied` Отказ

`server → attacker` · `safe` · `with-defence`
Сообщение: 403 · Итог: доступ запрещён

```text
403 Forbidden
```

#### Просто

Сервер отвечает «доступ запрещён». Атакующий сменил себе тему оформления — и только.

#### По шагам

Загрязнения не случилось, а проверка прав смотрит только на собственные поля пользователя. Все
остальные посетители работают как раньше.

#### Глубже

Найти уязвимые места помогает поиск по коду: рекурсивное слияние, глубокое копирование, запись по
пути из точек, перебор `for…in` по данным посетителя. Библиотеки с такими функциями стоит держать
обновлёнными.

## Как защититься

- **Отбрасывайте опасные ключи.** При слиянии, копировании и записи по пути пропускайте
  `__proto__`, `constructor` и `prototype` и перебирайте только собственные ключи (`Object.keys`).
- **Проверяйте запрос по схеме.** Разрешённые поля перечислены, лишние отвергаются.
- **Данные посетителя — не в обычные объекты.** Для словарей с ключами от посетителя берите `Map`
  или объекты без прототипа: `Object.create(null)`.
- **Заморозьте прототип.** `Object.freeze(Object.prototype)` в начале программы не даёт его менять.
  Проверьте, что библиотеки с этим работают.
- **Проверяйте собственные поля.** Для прав и настроек — `Object.hasOwn` и явные значения по
  умолчанию, а не поиск по цепочке прототипов.
- **Обновляйте библиотеки.** Уязвимые функции слияния находили во многих популярных пакетах.
