## Шаги

### `form` Проверка связи

`attacker → server` · `legit`
Сообщение: ping 192.0.2.10 · Итог: ответ ping

```http
GET /ping?host=192.0.2.10
```

#### Просто

На сайте есть полезная кнопка: впиши адрес компьютера, и сайт проверит, отвечает ли он. Атакующий
сначала пользуется ей как все.

#### По шагам

Браузер отправляет адрес `192.0.2.10` в поле `host`. Сервер запускает программу `ping` с этим
адресом и показывает на странице, что она напечатала.

#### Глубже

Для такой проверки сайту проще всего вызвать готовую программу системы, а не писать свою. Опасно
не это, а то, *как* он её вызывает: дальше всё решит, попадёт ли ввод посетителя в командную
оболочку.

### `trick` Адрес с хвостом

`attacker → server` · `attack`
Сообщение: адрес + ;id · Итог: принято как адрес

```http
GET /ping?host=192.0.2.10⟦;id⟧
```

#### Просто

Теперь после адреса атакующий дописывает точку с запятой и короткое слово `id`. Для человека это
мусор. Для командной строки сервера **точка с запятой значит «а теперь следующая команда»**.

#### По шагам

В поле `host` уходит строка `192.0.2.10;id`. Сервер не проверяет, похожа ли она на адрес, и
принимает целиком.

#### Глубже

`id` — безобидная команда Unix: она печатает, от имени какого пользователя запущена. Атакующему
она нужна как проверка: если её ответ появится на странице, значит, сервер выполняет его команды.
Кроме `;` команды связывают знаки `&`, `&&`, `|` и `||`, а особый смысл у оболочки есть ещё у
`$`, `<`, `>`, кавычек и скобок.

### `glue` Сервер склеивает команду

`server → os` · `attack` · `without-defence`
Сообщение: sh -c "ping ...;id" · Итог: атака

```sh
sh -c "ping -c 1 192.0.2.10⟦;id⟧"
```

#### Просто

Сервер пишет команду как одну строку: «ping», пробел и то, что ввёл посетитель. Готовую строку он
отдаёт **командной оболочке** — программе, которая читает строку и решает, что запустить.

#### По шагам

Код сайта вызывает функцию вроде `system("ping -c 1 " + host)`. Такая функция передаёт строку
оболочке `sh`. Оболочка делит её по своим правилам и видит две команды: `ping -c 1 192.0.2.10` и
`id`.

#### Глубже

Ввод стал частью команды: это ошибка CWE-78. MITRE описывает именно этот вариант: программа хочет
запустить одну свою программу, а ввод посетителя подставляет как её аргумент. Не убрав из ввода
разделители команд, она даёт атакующему запустить что-то после неё.

### `run` Две команды вместо одной

`os → server` · `attack` · `without-defence`
Сообщение: ping + вывод id · Итог: команда выполнена

```text
64 bytes from 192.0.2.10: icmp_seq=1
⟦uid=33(www-data) gid=33(www-data)⟧
```

#### Просто

Система послушно выполняет обе команды подряд. Сначала `ping`, потом `id`. Вывод обеих возвращается
сайту одним куском.

#### По шагам

Вторая команда работает с теми же правами, что и сам сайт: здесь это пользователь `www-data`. Всё,
что можно ему, теперь можно и атакующему.

#### Глубже

Вместо `id` могла стоять любая команда: прочитать файлы настроек с паролями от базы, скачать и
запустить программу, открыть соединение наружу. Это удалённое выполнение кода. Чем больше прав у
учётной записи сайта, тем больше ущерб.

### `leak` Ответ на странице

`server → attacker` · `attack` · `without-defence`
Сообщение: страница с uid=33 · Итог: сервер под контролем

#### Просто

Сайт показывает всё, что напечатали программы, и атакующий видит на странице ответ своей команды.
Значит, теперь он может командовать сервером.

#### По шагам

Сервер вставляет вывод в страницу как обычно. Строка `uid=33(www-data)` подтверждает: вторая
команда выполнилась.

#### Глубже

Вывод на странице только облегчает атаку. Если бы сайт его не показывал, вторая команда всё равно
выполнилась бы: записала файл, удалила данные, запустила программу. Поэтому «мы ничего не
выводим» — не защита.

### `args` Запуск без оболочки

`server → os` · `attack` · `with-defence` · `stopped`
Сообщение: ping + 1 аргумент · Итог: одна программа, атака не сработала

```text
программа:  ping
аргументы:  -c | 1 | ⟦192.0.2.10;id⟧
```

#### Просто

Теперь сервер не пишет команду одной строкой. Он называет системе программу и **отдельно
перечисляет её аргументы**, как пункты списка. Оболочка не участвует, а значит, точку с запятой
некому понимать как «следующая команда». Атака останавливается здесь.

#### По шагам

Сервер вызывает `ping` напрямую и передаёт ввод посетителя одним аргументом. Система запускает
одну программу, `ping`, и отдаёт ей строку `192.0.2.10;id` целиком.

#### Глубже

Это параметризация по OWASP: устройство команды задано заранее, а данные идут отдельно, как
параметры в SQL-запросе. В Java так работает `ProcessBuilder`: программа и каждый аргумент —
отдельные элементы списка. Ещё лучше обойтись совсем без внешней программы, если в языке есть
готовая функция. OWASP предупреждает: список аргументов не спасает от вредного *аргумента*,
поэтому ввод всё равно проверяют.

### `fail` Нет такого адреса

`os → server` · `safe` · `with-defence`
Сообщение: ping: unknown host · Итог: команда id не запускалась

#### Просто

`ping` не находит компьютер с таким странным именем и сообщает об ошибке. Вторая команда так и не
запустилась.

#### По шагам

Строка `192.0.2.10;id` для `ping` — просто имя, которого нет. Программа завершается с ошибкой.

#### Глубже

Вторым слоем сервер проверяет ввод по белому списку ещё до запуска: только цифры и точки, длина
не больше нужной. Такой ввод вообще не дошёл бы до `ping`. Но проверка лишь дополняет запуск без
оболочки, а не заменяет его.

### `refuse` Ошибка вместо ответа

`server → attacker` · `safe` · `with-defence`
Сообщение: Адрес не найден · Итог: атака не удалась

#### Просто

Сайт отвечает: такой адрес не найден. Атакующий не получил ничего, кроме этой фразы.

#### По шагам

Сервер показывает короткое сообщение об ошибке. Вывода второй команды нет, потому что она не
выполнялась.

#### Глубже

Даже если ошибка где-то останется, учётная запись сайта с минимальными правами ограничит ущерб.
OWASP советует запускать приложение с наименьшими нужными правами и отдельной учётной записью
под одну задачу.

## Как защититься

- **Не вызывать внешние программы без нужды.** Если в языке есть готовая функция (создать папку,
  сжать файл), используйте её: её нельзя заставить сделать что-то другое.
- **Программа и аргументы — отдельно.** Если без программы не обойтись, запускайте её списком
  аргументов, без командной оболочки: ввод посетителя остаётся одним аргументом.
- **Проверка ввода по белому списку.** Команду выбирает сервер из своего списка, аргументы
  сверяются с разрешёнными значениями или строгим шаблоном: только нужные знаки, без пробелов,
  кавычек, скобок и `&`, `|`, `;`, `$`, `<`, `>`, `\`, `` ` ``, `!`.
- **Экранирование — слабее списка аргументов.** Функции вроде `escapeshellarg()` в PHP заключают ввод в
  кавычки, но атакующий всё ещё может передать программе свой аргумент.
- **Минимальные права.** Сайт работает от учётной записи, которой можно только то, что нужно ему.
  Это не останавливает внедрение, но уменьшает ущерб.
