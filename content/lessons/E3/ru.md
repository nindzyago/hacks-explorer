## Шаги

### `forgot` «Я забыл пароль» от чужого имени

`attacker → server` · `attack`
Сообщение: сброс пароля для Анны · Итог: принят

```http
POST /forgot-password
Host: ⟦evil.example⟧

email=anna@mail.example
```

#### Просто

Атакующий открывает форму «Забыли пароль?» интернет-магазина и вписывает почту **Анны**. Но в
запросе он подменяет **заголовок Host** — имя сайта, к которому обращается браузер, — на свой
домен.

#### По шагам

Браузер сам пишет в каждый запрос заголовок `Host` с именем сайта. Но атакующий отправляет запрос
не из браузера, а своей программой, и пишет туда что хочет. Сервер магазина отвечает на любые
имена, поэтому запрос всё равно доходит.

#### Глубже

RFC 9110, раздел 7.2: заголовок `Host` сообщает имя и порт из адреса, чтобы один сервер мог
обслуживать несколько сайтов. Это данные от клиента, как и любые другие. OWASP в WSTG-INPV-17
отмечает: если сервер отвергает чужой `Host`, проверяют ещё и `X-Forwarded-Host`, который
некоторые серверы учитывают вместо него.

### `letter` Письмо со ссылкой на чужой домен

`server → mail` · `attack` · `without-defence`
Сообщение: письмо «Сброс пароля» · Итог: ссылка ведёт на evil.example

```text
Чтобы задать новый пароль, перейдите по ссылке:
https://⟦evil.example⟧/reset?token=Q7xK2m
```

#### Просто

Магазин создаёт для Анны секретную **ссылку для сброса** пароля. Адрес сайта в ссылке он берёт из
заголовка Host — и получается ссылка **на сайт атакующего**. Письмо уходит Анне, настоящее, от
магазина.

#### По шагам

Код сброса склеивает ссылку так: `https://` + значение `Host` + `/reset?token=` + новый токен.
Токен настоящий и действует для учётной записи Анны. Неправилен только домен перед ним.

#### Глубже

Это настоящее письмо магазина с его обратным адресом: подделывать ничего не нужно, магазин сам
вложил в него чужую ссылку. MITRE не выделяет эту ошибку в
отдельный номер, ближайший класс — слабый механизм восстановления пароля, CWE-640.

### `click` Анна нажимает ссылку

`browser → attacker` · `attack` · `without-defence`
Сообщение: GET /reset с токеном · Итог: токен у атакующего

```http
GET /reset?token=⟦Q7xK2m⟧
Host: evil.example
```

#### Просто

Анна не просила сброс, но письмо выглядит настоящим, и она нажимает ссылку. Браузер открывает
сайт атакующего и **приносит туда секретный токен**.

#### По шагам

Токен стоит прямо в адресе ссылки, поэтому сервер атакующего видит его в первой же строке
запроса и записывает. Анна может увидеть ошибку или пустую страницу — уже неважно.

#### Глубже

OWASP в WSTG-INPV-17 называет это отравлением сброса пароля: жертва переходит по ссылке, и
секретный токен попадает к атакующему. Сломан не токен, а адрес, который сервер приклеил перед ним.

### `takeover` Атакующий задаёт новый пароль

`attacker → server` · `attack` · `without-defence`
Сообщение: новый пароль · Итог: учётная запись захвачена

```http
POST /reset
Host: shop.example

token=⟦Q7xK2m⟧&password=…
```

#### Просто

Атакующий идёт на **настоящий** сайт магазина с токеном Анны и задаёт новый пароль. Теперь он
входит в её учётную запись, а Анна — нет.

#### По шагам

Сервер проверяет токен: он выдан для Анны, не использован и не истёк. Всё сходится, пароль
меняется.

#### Глубже

Короткий срок жизни токена и одноразовость, которые советует OWASP, здесь не помогают: атакующий
пользуется токеном сразу, пока тот свежий. Защита должна стоять раньше — там, где строится ссылка.

### `config` Ссылка строится из настроек

`server → server` · `attack` · `with-defence` · `stopped`
Сообщение: чужой Host · Итог: не используется, атака не сработала

```text
адрес сайта в настройках: https://shop.example
⟦Host: evil.example⟧  → не используется для ссылок
```

#### Просто

Магазин берёт адрес сайта для ссылок **из своих настроек**, а не из заголовка Host. Что бы ни
написал атакующий, ссылка ведёт на shop.example. Здесь атака и останавливается.

#### По шагам

Адрес сайта записан в конфигурации один раз. Код сброса склеивает ссылку из него и токена.
Заголовок `Host` для этого больше не нужен.

#### Глубже

OWASP Forgot Password Cheat Sheet прямо советует не полагаться на `Host` при создании ссылок
сброса: адрес задаётся жёстко или сверяется со списком доверенных доменов. Второй слой — веб-сервер,
который отвечает только на свои имена, а запросы с чужим `Host` отклоняет.

### `letter-safe` Письмо с настоящей ссылкой

`server → mail` · `safe` · `with-defence`
Сообщение: письмо «Сброс пароля» · Итог: ссылка ведёт на shop.example

```text
Чтобы задать новый пароль, перейдите по ссылке:
https://shop.example/reset?token=Q7xK2m
```

#### Просто

Анна получает письмо, о котором не просила, но ссылка в нём ведёт **на сам магазин**. Токен
атакующему не достаётся.

#### По шагам

Ссылка и токен в ней известны только Анне. Атакующий видел лишь ответ «письмо отправлено» и
ничего с ним сделать не может.

#### Глубже

Письмо стоит дополнить строкой «если вы не просили сброс, просто проигнорируйте это письмо»: так
человек не испугается и не станет что-то менять сам.

### `read-safe` Анна не просила сброс и не трогает письмо

`mail → browser` · `safe` · `with-defence`
Сообщение: письмо магазина · Итог: пароль прежний

```text
токен Q7xK2m не использован и скоро истечёт
```

#### Просто

Анна видит письмо о сбросе, которого не просила, и просто его не трогает. Её пароль остаётся
прежним.

#### По шагам

Неиспользованный токен истекает сам. Даже если Анна нажмёт ссылку, она попадёт на настоящий сайт
магазина, где новый пароль задаст только она.

#### Глубже

Сам запрос сброса учётную запись не меняет. OWASP советует ничего не менять, например не
блокировать вход, пока не предъявлен действующий токен, и одинаково отвечать для существующих и
несуществующих адресов почты.

## Как защититься

- **Адрес сайта из настроек.** Ссылки в письмах, перенаправления и абсолютные адреса стройте из
  настроек сайта, а не из заголовков `Host`, `X-Forwarded-Host` или `Forwarded`.
- **Только свои имена.** Веб-сервер передаёт приложению только запросы на имена из списка
  разрешённых, а запросы с чужим `Host` отклоняет раньше, чем их увидит приложение.
- **Пересылочные заголовки — только от своего прокси.** `X-Forwarded-Host` учитывайте, только если
  его поставил ваш прокси, и сверяйте значение со списком.
- **Правильные токены сброса.** Из криптографически стойкого генератора случайных чисел, длинные,
  одноразовые, с ограниченным сроком жизни, как советует OWASP. Они не спасут от подменённой
  ссылки, но сократят окно для других атак.
- **Проверьте все письма.** Подтверждение почты, приглашения, ссылки для входа — везде, где сервер
  вставляет в письмо адрес сайта, его должен давать конфиг.
