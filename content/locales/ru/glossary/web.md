# Веб и базы данных

## `web-server` Веб-сервер

`category` web · `see` query, database · `lessons` B1

Формы: веб-сервер, веб-сервера, веб-серверу, веб-сервером, веб-сервере

Программа на компьютере сайта, которая принимает запросы браузеров и отвечает на них: отдаёт
страницы, проверяет логин и пароль, обращается к базе данных.

## `database` База данных

`category` web · `see` sql, query, hash · `lessons` B1

Формы: база данных, базы данных, базе данных, базу данных, базой данных, базам данных, базах данных

Хранилище сведений сайта: пользователи, заказы, хеши паролей. Сайт читает и меняет в ней данные
запросами, чаще всего на языке SQL.

## `sql` SQL

`category` web · `see` query, database, sql-injection · `lessons` B1

Формы: SQL

Structured Query Language — язык запросов к реляционным базам данных. Например,
`SELECT * FROM users WHERE login = 'anna'` значит «найди в таблице users строки с логином anna».

## `query` Запрос

`category` web · `see` sql, web-server, parameterized-query · `lessons` B1

Формы: запрос, запроса, запросу, запросом, запросе, запросы, запросов, запросам, запросами, запросах

Обращение одной программы к другой с просьбой что-то сделать или отдать. Браузер отправляет
запросы веб-серверу по протоколу HTTP, сервер — базе данных на языке SQL.

## `injection` Инъекция

`category` web · `see` sql-injection, trust-boundary, owasp · `lessons` B1

Формы: инъекция, инъекции, инъекцию, инъекцией, инъекций, инъекциям, инъекциях

Класс атак, в которых данные от пользователя программа принимает за часть команды и выполняет.
Бывают инъекции в запросы к базе данных, в команды операционной системы, в страницы сайта.

## `sql-injection` SQL-инъекция

`category` web · `see` injection, parameterized-query, sql-comment, cwe · `lessons` B1

Формы: SQL-инъекция, SQL-инъекции, SQL-инъекцию, SQL-инъекцией, SQL-инъекций

Инъекция в запрос к базе данных: сервер вклеивает присланный текст в SQL-запрос, и этот текст
меняет смысл запроса. Класс ошибки — CWE-89; в OWASP Top 10:2021 она входит в пункт A03 Injection
(уроки ссылаются на выпуск 2021 года; в 2025 году вышел новый).

## `parameterized-query` Параметризованный запрос

`category` web · `see` sql-injection, query · `lessons` B1

Формы: параметризованный запрос, параметризованного запроса, параметризованному запросу, параметризованным запросом, параметризованном запросе, параметризованные запросы, параметризованных запросов, параметризованными запросами, подготовленный запрос, подготовленные запросы, prepared statement

Запрос, в котором команда и данные пользователя передаются базе данных отдельно: на месте данных
в тексте запроса стоят метки-параметры. База всегда считает подставленное значением, а не частью
команды, поэтому кавычки и `--` во вводе ничего не ломают. Главная защита от SQL-инъекции по
рекомендациям OWASP.

## `sql-comment` Комментарий SQL

`category` web · `see` sql-injection, sql · `lessons` B1

Формы: комментарий SQL, комментария SQL, комментарием SQL, SQL-комментарий, SQL-комментария, SQL-комментарием

Часть SQL-запроса, которую база данных пропускает. Две чёрточки `--` начинают комментарий до
конца строки (в MySQL после них нужен пробел или другой пробельный символ). В SQL-инъекции так отрезают остаток запроса,
например проверку пароля.

## `hash` Хеш

`category` web · `see` database · `lessons` B1

Формы: хеш, хеша, хешу, хешем, хеше, хеши, хешей, хешам, хешами, хешах

Значение фиксированной длины, которое хеш-функция вычисляет из данных. У криптографических
хеш-функций обратный путь — только перебор догадок. Правильно сделанные сайты хранят не пароли, а
их хеши, посчитанные медленными функциями с «солью», например Argon2 или bcrypt.

## `xss` XSS

`category` web · `see` injection, output-encoding, csp, session-cookie · `lessons` C1, C2, C3

Формы: XSS, межсайтовый скриптинг, межсайтового скриптинга, межсайтовым скриптингом

Межсайтовый скриптинг (*cross-site scripting*): сайт вставляет присланный текст в свою страницу
так, что браузер выполняет его как скрипт сайта. Отражённый XSS возвращает ввод из запроса сразу
в ответ, хранимый сначала сохраняет его, а DOM XSS собирает страница в браузере. Класс ошибки —
CWE-79; в OWASP Top 10:2021 входит в пункт A03 Injection.

## `output-encoding` Экранирование вывода

`category` web · `see` xss, csp · `lessons` C1

Формы: экранирование вывода, экранирования вывода, экранированию вывода, экранированием вывода

Замена особых знаков безопасными записями в момент, когда данные вставляются в страницу: `<`
становится `&lt;`, `"` становится `&quot;`. Браузер показывает такие знаки как текст, но тег или
атрибут из них уже не начнётся. Правило своё для каждого места: текст страницы, атрибут,
JavaScript, CSS, адрес. Главная защита от XSS по рекомендациям OWASP.

## `sanitizer` Санитайзер HTML

`category` web · `see` xss, output-encoding · `lessons` C2

Формы: санитайзер, санитайзера, санитайзеру, санитайзером, санитайзере, санитайзеры, санитайзеров

Фильтр, который разбирает присланный HTML и оставляет только разрешённые теги и атрибуты, а
скрипты и обработчики событий удаляет. Нужен там, где пользователю разрешено оформление и простое
экранирование сломало бы разметку. OWASP советует готовую библиотеку DOMPurify, а не самодельный
фильтр.

## `csp` Content Security Policy

`category` web · `see` xss, output-encoding · `lessons` C1

Формы: Content Security Policy, CSP

Политика безопасности содержимого: заголовок ответа, которым сайт говорит браузеру, откуда можно
загружать скрипты и другие ресурсы. Без `'unsafe-inline'` в правиле `script-src` браузер не
выполняет скрипты, вписанные прямо в страницу. Описана в спецификации W3C; защищает вторым слоем,
если экранирование где-то забыли.

## `trusted-types` Trusted Types

`category` web · `see` xss, csp, sanitizer · `lessons` C3

Формы: Trusted Types

Защита браузера от DOM XSS. Правило `require-trusted-types-for 'script'` в Content Security Policy
запрещает записывать простые строки в опасные приёмники вроде `innerHTML`: данные сначала
проходят через политику сайта, например санитайзер. Описана в спецификации W3C.

## `session-cookie` Cookie сессии

`category` web · `see` xss, web-server, csrf, samesite, session-fixation · `lessons` C1, C4, D3

Формы: cookie сессии, куки сессии, сессионный cookie

Небольшая запись, которую сайт оставляет в браузере после входа. Браузер прикладывает её к каждому
запросу на этот сайт, и по ней сайт узнаёт пользователя без пароля. Кто украл такой cookie, может
войти как владелец. Атрибут `HttpOnly` (RFC 6265) запрещает скриптам страницы читать его.

## `csrf` CSRF

`category` web · `see` csrf-token, session-cookie, samesite · `lessons` C4

Формы: CSRF, подделка межсайтового запроса, подделки межсайтового запроса, подделку межсайтового запроса, подделкой межсайтового запроса

Подделка межсайтового запроса (*Cross-Site Request Forgery*): чужая страница заставляет браузер
жертвы отправить запрос на сайт, где жертва уже вошла. Браузер сам прикладывает её cookie, и сайт
выполняет действие от её имени: перевод, смену пароля. В каталоге MITRE это слабость CWE-352 и шаблон атаки CAPEC-62.

## `csrf-token` CSRF-токен

`category` web · `see` csrf, session-cookie · `lessons` C4

Формы: CSRF-токен, CSRF-токена, CSRF-токену, CSRF-токеном, CSRF-токене, CSRF-токены

Случайная секретная строка, которую сайт кладёт в свои формы и сверяет при каждом запросе,
который что-то меняет. Чужая страница её не знает и прочитать со страницы сайта не может, поэтому
поддельный запрос приходит без токена и отклоняется.

## `samesite` SameSite

`category` web · `see` session-cookie, csrf · `lessons` C4

Формы: SameSite

Атрибут cookie, который говорит браузеру, прикладывать ли его к запросам с других сайтов. `Strict`
— никогда, `Lax` — только при переходе на страницу безопасным методом, например по ссылке, `None` —
всегда. Защищает от CSRF как
дополнительный слой, но не заменяет CSRF-токен.

## `same-origin-policy` Правило одного происхождения

`category` web · `see` cors, clickjacking · `lessons` C6

Формы: правило одного происхождения, правила одного происхождения, правилу одного происхождения, правилом одного происхождения, правиле одного происхождения, same-origin policy

Главное правило безопасности браузера (*same-origin policy*): скрипт одного происхождения не
читает ответы другого. Происхождение (*origin*) — это схема, имя и порт: `https://shop.example` и
`https://api.shop.example` — разные происхождения, хотя это один сайт.

## `cors` CORS

`category` web · `see` same-origin-policy, session-cookie · `lessons` C6

Формы: CORS

Cross-Origin Resource Sharing — способ, которым сервер разрешает скриптам других сайтов читать
свои ответы, ослабляя правило одного происхождения. Разрешение — заголовок
`Access-Control-Allow-Origin`. Слишком широкое разрешение — ошибка CWE-942.

## `clickjacking` Clickjacking

`category` web · `see` same-origin-policy, session-cookie · `lessons` C5

Формы: clickjacking, кликджекинг, кликджекинга, кликджекингу, кликджекингом

«Угон клика»: чужой сайт показывает настоящую страницу в прозрачной рамке поверх своей кнопки, и
пользователь, сам того не зная, нажимает кнопку настоящего сайта. Класс ошибки — CWE-1021. Защита
— заголовок с правилом `frame-ancestors` или `X-Frame-Options`.

## `idor` IDOR

`category` web · `see` authorization, owasp, cwe · `lessons` D1

Формы: IDOR

Insecure Direct Object Reference — небезопасная прямая ссылка на объект. Сервер выдаёт запись по
номеру из запроса (например, заказ `/orders/1002`) и не проверяет, что она принадлежит тому, кто
спрашивает. Поменяв номер, можно увидеть или изменить чужое. Ближайший класс в MITRE — CWE-639; в OWASP Top
10:2021 входит в пункт A01 Broken Access Control. В API ту же ошибку зовут BOLA.

## `authorization` Авторизация

`category` web · `see` idor, web-server, privilege-escalation · `lessons` D1, D2

Формы: авторизация, авторизации, авторизацию, авторизацией, проверка прав, проверки прав, проверку прав, проверкой прав

Проверка того, что пользователю можно сделать: открыть эту запись, изменить её, удалить. Не путать
со входом (аутентификацией), который отвечает на вопрос «кто ты». Сервер делает её сам при каждом
запросе и по умолчанию отказывает.

## `privilege-escalation` Повышение привилегий

`category` web · `see` authorization, idor · `lessons` D2

Формы: повышение привилегий, повышения привилегий, повышению привилегий, повышением привилегий, повышении привилегий

Получение прав, которых пользователю не давали. Вертикальное — обычный пользователь действует как
администратор; горизонтальное — получает доступ к данным другого пользователя с той же ролью.
Частая причина — служебный адрес без проверки прав на сервере. В MITRE это классы CWE-269 и
CWE-862, в OWASP Top 10:2021 — пункт A01 Broken Access Control.

## `session-fixation` Фиксация сессии

`category` web · `see` session-cookie, authorization · `lessons` D3

Формы: фиксация сессии, фиксации сессии, фиксацию сессии, фиксацией сессии

Атака, при которой атакующий заранее навязывает жертве известный ему номер сессии, например
ссылкой с этим номером. Если после входа сайт не выдаёт новый номер, сессия жертвы оказывается в
руках атакующего. В каталоге MITRE — CWE-384. Защита — новый случайный номер сессии после входа и
отказ принимать номер из адреса страницы.

## `jwt` JWT

`category` web · `see` session-cookie, authorization · `lessons` D4

Формы: JWT

JSON Web Token (RFC 7519) — пропуск из трёх частей: заголовок, данные и подпись, закодированные в
base64url и разделённые точками. Данные может прочитать любой; от изменения их защищает только
подпись, поэтому сервер обязан проверять её сам, с заранее заданным алгоритмом. Ошибка проверки
подписи — CWE-347.

## `oauth` OAuth

`category` web · `see` pkce, jwt · `lessons` D5

Формы: OAuth, OAuth 2.0

Протокол (RFC 6749), по которому сайт получает доступ к аккаунту пользователя на другом сервисе
без его пароля. Сервис входа возвращает браузер на зарегистрированный адрес возврата
(`redirect_uri`) с одноразовым кодом, и сайт меняет код на токен доступа. Современные правила
безопасности собраны в RFC 9700.

## `pkce` PKCE

`category` web · `see` oauth · `lessons` D5

Формы: PKCE

Proof Key for Code Exchange (RFC 7636). Приложение в начале входа по OAuth придумывает случайный
секрет и отправляет только его хеш; при обмене кода на токен оно показывает сам секрет. Код,
украденный по дороге, без секрета не обменять. RFC 9700 требует PKCE от публичных приложений и
рекомендует остальным.

## `salt` Соль

`category` web · `see` hash, password-hashing · `lessons` F1

Формы: соль, соли, солью, солей

Случайная строка, которую сайт добавляет к паролю перед хешированием, у каждого пароля своя. Соль
не секрет и хранится рядом с хешем. Из-за неё одинаковые пароли дают разные хеши, а заранее
посчитанные таблицы хешей бесполезны.

## `password-hashing` Хеш-функция для паролей

`category` web · `see` hash, salt · `lessons` F1

Формы: медленная хеш-функция, медленной хеш-функции, медленную хеш-функцию, медленной хеш-функцией, медленные хеш-функции, медленных хеш-функций, медленный хеш, медленного хеша

Хеш-функция, которая нарочно тратит заметное время, а иногда и память, на каждый хеш: Argon2id,
scrypt, bcrypt, PBKDF2. Для одного входа это незаметно, а перебор миллионов догадок по утёкшей
базе становится очень дорогим.

## `jndi` JNDI

`category` web · `see` ldap, logging · `lessons` K1

Формы: JNDI

Java Naming and Directory Interface — встроенный в Java способ найти объект по имени в службе
каталогов или имён: LDAP, DNS, RMI. В уязвимых версиях Log4j подстановка `${jndi:…}` в
сообщении журнала запускала такой поиск по адресу, который прислал атакующий.

## `ldap` LDAP

`category` web · `see` jndi · `lessons` K1

Формы: LDAP

Lightweight Directory Access Protocol — протокол служб каталогов, где организации хранят
учётные записи, группы и другие сведения (RFC 4511). Через JNDI программа на Java может
получить из каталога объект, а с ним и код.

## `command-injection` Внедрение команд ОС

`category` web · `see` injection, shell, rce, cwe · `lessons` B2

Формы: внедрение команд ОС, внедрения команд ОС, внедрению команд ОС, внедрением команд ОС, внедрение команд, внедрения команд, внедрению команд, внедрением команд, инъекция команд, инъекции команд, инъекцию команд, инъекцией команд

Инъекция в команду операционной системы: программа склеивает строку команды из своего текста и
присланных данных и отдаёт её командной оболочке. Знаки вроде `;`, `&` или `|` во вводе начинают
вторую команду, и сервер выполняет её со своими правами. Класс ошибки — CWE-78; в OWASP Top
10:2021 входит в пункт A03 Injection.

## `shell` Командная оболочка

`category` web · `see` command-injection · `lessons` B2

Формы: командная оболочка, командной оболочки, командную оболочку, командной оболочкой, оболочка, оболочки, оболочке, оболочку, оболочкой

Программа, которая читает строку команды, делит её на части и запускает программы: в Linux это
`sh` или `bash`, в Windows — `cmd.exe`. У неё свой язык: `;` разделяет команды, `|` передаёт вывод
одной программы другой, `$( )` подставляет вывод команды в строку. Поэтому строка, собранная из
чужого ввода, может значить для оболочки больше, чем задумал автор программы.

## `path-traversal` Обход каталогов

`category` web · `see` web-server, cwe · `lessons` B3

Формы: обход каталогов, обхода каталогов, обходу каталогов, обходом каталогов, обходе каталогов, path traversal, directory traversal

Атака на программу, которая собирает путь к файлу из присланного имени. `../` в пути значит
«папка выше», и несколько таких шагов выводят путь из разрешённой папки к любому файлу, который
программе можно читать. Класс ошибки — CWE-22; в OWASP Top 10:2021 входит в пункт A01 Broken
Access Control.

## `web-root` Веб-корень

`category` web · `see` web-server, web-shell · `lessons` B4

Формы: веб-корень, веб-корня, веб-корню, веб-корнем, веб-корне

Папка на сервере, из которой веб-сервер отдаёт файлы по адресам сайта: файл `uploads/a.png` в ней
открывается по адресу `/uploads/a.png`. Сервер, настроенный на PHP, файлы `.php` из этой папки не
отдаёт, а выполняет. Поэтому файлы посетителей хранят вне веб-корня.

## `web-shell` Веб-шелл

`category` web · `see` web-root, rce, mitre-attack · `lessons` B4

Формы: веб-шелл, веб-шелла, веб-шеллу, веб-шеллом, веб-шелле, веб-шеллы, веб-шеллов, web shell

Скрипт, который атакующий положил на веб-сервер, чтобы управлять сервером обычными запросами:
открыл адрес скрипта — сервер выполнил команду и вернул ответ. В MITRE ATT&CK это подтехника
T1505.003. Часто попадает на сервер через небезопасную загрузку файлов.

## `deserialization` Десериализация

`category` web · `see` gadget-chain, rce, cwe · `lessons` B5
