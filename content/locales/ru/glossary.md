## `attacker` Атакующий

`category` basics · `see` victim, trust-boundary · `lessons` B1, I1

Тот, кто пытается заставить систему работать не по правилам: украсть данные, войти под чужим
именем, остановить сервис. Вредные сообщения на схемах уроков красные.

## `victim` Жертва

`category` basics · `see` attacker, phishing · `lessons` I1

Формы: жертва, жертвы, жертве, жертву, жертвой

Человек или система, против которых направлена атака. В уроке о фишинге это сотрудник, у
которого выманивают пароль.

## `trust-boundary` Граница доверия

`category` basics · `see` injection, attacker · `lessons` B1

Формы: граница доверия, границы доверия, границе доверия, границу доверия, границей доверия

Место, где данные приходят от того, кому система не может доверять (например, из интернета), к
тому, кто им доверяет (сервер, база данных). Всё, что пересекает её снаружи, должны проверять и
обрабатывать как данные, а не как команды. На схеме урока её показывает рамка зоны.

## `web-server` Веб-сервер

`category` web · `see` query, database · `lessons` B1

Формы: веб-сервер, веб-сервера, веб-серверу, веб-сервером, веб-сервере

Программа на компьютере сайта, которая принимает запросы браузеров и отвечает на них: отдаёт
страницы, проверяет логин и пароль, обращается к базе данных.

## `database` База данных

`category` web · `see` sql, query, hash · `lessons` B1

Формы: база данных, базы данных, базе данных, базу данных, базой данных, базам данных, базах данных

Хранилище сведений сайта: пользователи, заказы, хеши паролей. Сайт читает и меняет в ней данные
запросами, чаще всего на языке SQL.

## `sql` SQL

`category` web · `see` query, database, sql-injection · `lessons` B1

Формы: SQL

Structured Query Language — язык запросов к реляционным базам данных. Например,
`SELECT * FROM users WHERE login = 'anna'` значит «найди в таблице users строки с логином anna».

## `query` Запрос

`category` web · `see` sql, web-server, parameterized-query · `lessons` B1

Формы: запрос, запроса, запросу, запросом, запросе, запросы, запросов, запросам, запросами, запросах

Обращение одной программы к другой с просьбой что-то сделать или отдать. Браузер отправляет
запросы веб-серверу по протоколу HTTP, сервер — базе данных на языке SQL.

## `injection` Инъекция

`category` web · `see` sql-injection, trust-boundary, owasp · `lessons` B1

Формы: инъекция, инъекции, инъекцию, инъекцией, инъекций, инъекциям, инъекциях

Класс атак, в которых данные от пользователя программа принимает за часть команды и выполняет.
Бывают инъекции в запросы к базе данных, в команды операционной системы, в страницы сайта.

## `sql-injection` SQL-инъекция

`category` web · `see` injection, parameterized-query, sql-comment, cwe · `lessons` B1

Формы: SQL-инъекция, SQL-инъекции, SQL-инъекцию, SQL-инъекцией, SQL-инъекций

Инъекция в запрос к базе данных: сервер вклеивает присланный текст в SQL-запрос, и этот текст
меняет смысл запроса. Класс ошибки — CWE-89; в OWASP Top 10:2021 она входит в пункт A03 Injection
(уроки ссылаются на выпуск 2021 года; в 2025 году вышел новый).

## `parameterized-query` Параметризованный запрос

`category` web · `see` sql-injection, query · `lessons` B1

Формы: параметризованный запрос, параметризованного запроса, параметризованному запросу, параметризованным запросом, параметризованном запросе, параметризованные запросы, параметризованных запросов, параметризованными запросами, подготовленный запрос, подготовленные запросы, prepared statement

Запрос, в котором команда и данные пользователя передаются базе данных отдельно: на месте данных
в тексте запроса стоят метки-параметры. База всегда считает подставленное значением, а не частью
команды, поэтому кавычки и `--` во вводе ничего не ломают. Главная защита от SQL-инъекции по
рекомендациям OWASP.

## `sql-comment` Комментарий SQL

`category` web · `see` sql-injection, sql · `lessons` B1

Формы: комментарий SQL, комментария SQL, комментарием SQL, SQL-комментарий, SQL-комментария, SQL-комментарием

Часть SQL-запроса, которую база данных пропускает. Две чёрточки `--` начинают комментарий до
конца строки (в MySQL после них нужен пробел или другой пробельный символ). В SQL-инъекции так отрезают остаток запроса,
например проверку пароля.

## `hash` Хеш

`category` web · `see` database · `lessons` B1

Формы: хеш, хеша, хешу, хешем, хеше, хеши, хешей, хешам, хешами, хешах

Значение фиксированной длины, которое хеш-функция вычисляет из данных. У криптографических
хеш-функций обратный путь — только перебор догадок. Правильно сделанные сайты хранят не пароли, а
их хеши, посчитанные медленными функциями с «солью», например Argon2 или bcrypt.

## `xss` XSS

`category` web · `see` injection, output-encoding, csp, session-cookie · `lessons` C1

Формы: XSS, межсайтовый скриптинг, межсайтового скриптинга, межсайтовым скриптингом

Межсайтовый скриптинг (*cross-site scripting*): сайт вставляет присланный текст в свою страницу
так, что браузер выполняет его как скрипт сайта. Отражённый XSS возвращает ввод из запроса сразу
в ответ, хранимый сначала сохраняет его, а DOM XSS собирает страница в браузере. Класс ошибки —
CWE-79; в OWASP Top 10:2021 входит в пункт A03 Injection.

## `output-encoding` Экранирование вывода

`category` web · `see` xss, csp · `lessons` C1

Формы: экранирование вывода, экранирования вывода, экранированию вывода, экранированием вывода

Замена особых знаков безопасными записями в момент, когда данные вставляются в страницу: `<`
становится `&lt;`, `"` становится `&quot;`. Браузер показывает такие знаки как текст, но тег или
атрибут из них уже не начнётся. Правило своё для каждого места: текст страницы, атрибут,
JavaScript, CSS, адрес. Главная защита от XSS по рекомендациям OWASP.

## `csp` Content Security Policy

`category` web · `see` xss, output-encoding · `lessons` C1

Формы: Content Security Policy, CSP

Политика безопасности содержимого: заголовок ответа, которым сайт говорит браузеру, откуда можно
загружать скрипты и другие ресурсы. Без `'unsafe-inline'` в правиле `script-src` браузер не
выполняет скрипты, вписанные прямо в страницу. Описана в спецификации W3C; защищает вторым слоем,
если экранирование где-то забыли.

## `session-cookie` Cookie сессии

`category` web · `see` xss, web-server, csrf, samesite · `lessons` C1, C4

Формы: cookie сессии, куки сессии, сессионная cookie, сессионную cookie

Небольшая запись, которую сайт оставляет в браузере после входа. Браузер прикладывает её к каждому
запросу на этот сайт, и по ней сайт узнаёт пользователя без пароля. Кто украл такой cookie, может
войти как владелец. Атрибут `HttpOnly` (RFC 6265) запрещает скриптам страницы читать его.

## `csrf` CSRF

`category` web · `see` csrf-token, session-cookie, samesite · `lessons` C4

Формы: CSRF, подделка межсайтового запроса, подделки межсайтового запроса, подделку межсайтового запроса, подделкой межсайтового запроса

Подделка межсайтового запроса (*Cross-Site Request Forgery*): чужая страница заставляет браузер
жертвы отправить запрос на сайт, где жертва уже вошла. Браузер сам прикладывает её cookie, и сайт
выполняет действие от её имени: перевод, смену пароля. В каталоге MITRE это CWE-352.

## `csrf-token` CSRF-токен

`category` web · `see` csrf, session-cookie · `lessons` C4

Формы: CSRF-токен, CSRF-токена, CSRF-токену, CSRF-токеном, CSRF-токене, CSRF-токены

Случайная секретная строка, которую сайт кладёт в свои формы и сверяет при каждом запросе,
который что-то меняет. Чужая страница её не знает и прочитать со страницы сайта не может, поэтому
поддельный запрос приходит без токена и отклоняется.

## `samesite` SameSite

`category` web · `see` session-cookie, csrf · `lessons` C4

Формы: SameSite

Атрибут cookie, который говорит браузеру, прикладывать ли её к запросам с других сайтов. `Strict`
— никогда, `Lax` — только при обычном переходе по ссылке, `None` — всегда. Защищает от CSRF как
дополнительный слой, но не заменяет CSRF-токен.

## `idor` IDOR

`category` web · `see` authorization, owasp, cwe · `lessons` D1

Формы: IDOR

Insecure Direct Object Reference — небезопасная прямая ссылка на объект. Сервер выдаёт запись по
номеру из запроса (например, заказ `/orders/1002`) и не проверяет, что она принадлежит тому, кто
спрашивает. Поменяв номер, можно увидеть или изменить чужое. Класс ошибки — CWE-639; в OWASP Top
10:2021 входит в пункт A01 Broken Access Control. В API ту же ошибку зовут BOLA.

## `authorization` Авторизация

`category` web · `see` idor, web-server · `lessons` D1

Формы: авторизация, авторизации, авторизацию, авторизацией, проверка прав, проверки прав, проверку прав, проверкой прав

Проверка того, что пользователю можно сделать: открыть эту запись, изменить её, удалить. Не путать
со входом (аутентификацией), который отвечает на вопрос «кто ты». Сервер делает её сам при каждом
запросе и по умолчанию отказывает.


## `phishing` Фишинг

`category` people · `see` fake-page, proxy-phishing, social-engineering, mitre-attack · `lessons` I1

Формы: фишинг, фишинга, фишингу, фишингом, фишинге

Обман, при котором человеку пишут от имени банка, начальника или службы поддержки и заманивают на
поддельную страницу или просят сообщить секрет. В MITRE ATT&CK это техника T1566.

## `social-engineering` Социальная инженерия

`category` people · `see` phishing · `lessons` I1

Формы: социальная инженерия, социальной инженерии, социальную инженерию, социальной инженерией

Атака не на программу, а на человека: срочность, страх, авторитет и доверие заставляют сделать то,
что нужно атакующему, — открыть ссылку, назвать код, перевести деньги.

## `fake-page` Поддельная страница

`category` people · `see` domain, phishing, password-manager · `lessons` I1

Формы: поддельная страница, поддельной страницы, поддельной странице, поддельную страницу, поддельной страницей, поддельные страницы

Копия настоящей страницы входа на чужом адресе. Всё, что в неё вводят, получает атакующий.
Отличить её можно по домену в адресной строке, а не по виду: картинки и логотип скопировать легко.

## `domain` Домен

`category` people · `see` fake-page, password-manager, passkey · `lessons` I1

Формы: домен, домена, домену, доменом, домене, домены, доменов, доменам, доменами, доменах

Имя сайта в адресе, например `bank.example`. Чей это сайт, говорит конец имени, а не похожие
слова в нём: `login.bank.example` — сайт `bank.example`, а `bank.example.evil.example` — сайт
`evil.example`; `bank-login.example` — тоже другой домен, как бы похоже он ни выглядел. В уроках
домены взяты из учебной зоны `.example`, настоящих компаний здесь нет.

## `password-manager` Менеджер паролей

`category` people · `see` domain, fake-page, second-factor · `lessons` I1

Формы: менеджер паролей, менеджера паролей, менеджеру паролей, менеджером паролей, менеджере паролей, менеджеры паролей

Программа, которая хранит пароли и подставляет их только на сайте, для которого пароль сохранён.
На поддельной странице она пароль не предложит, и это повод проверить адрес.

## `second-factor` Второй фактор

`category` people · `see` passkey, proxy-phishing, password-manager · `lessons` I1

Формы: второй фактор, второго фактора, второму фактору, вторым фактором, втором факторе, двухфакторная аутентификация, двухфакторной аутентификации

Ещё одно подтверждение входа кроме пароля: код из приложения или СМС, уведомление на телефоне,
аппаратный ключ. Одного украденного пароля тогда мало. Коды из СМС и приложений можно выманить на
поддельной странице, ключи FIDO2 и passkeys — нет.

## `passkey` Passkey

`category` people · `see` second-factor, domain · `lessons` I1

Формы: passkey, passkeys

Вход без пароля по ключу, который хранится на устройстве или в менеджере паролей. Ключ привязан к
домену сайта, поэтому браузер не даст воспользоваться им на поддельной странице. Работает по
стандартам WebAuthn и FIDO2, как и аппаратные ключи FIDO2, которые часто служат вторым фактором
рядом с паролем.

## `proxy-phishing` Прокси-фишинг

`category` people · `see` phishing, second-factor, passkey · `lessons` I1

Формы: прокси-фишинг, прокси-фишинга, прокси-фишингу, прокси-фишингом, прокси-фишинге

Фишинг, при котором поддельная страница тут же пересылает всё введённое настоящему сайту и
показывает его ответы. Так атакующий получает и пароль, и одноразовый код, и открытую сессию.
Устойчивы к нему способы входа, привязанные к домену, например passkeys.

## `spf` SPF

`category` mail · `see` dkim, dmarc · `lessons` I1

Формы: SPF

Sender Policy Framework (RFC 7208): запись в DNS домена со списком серверов, которым разрешено
отправлять почту от его имени. Сервер получателя сверяет с ней сервер, приславший письмо.
Проверяется адрес из «конверта» письма, а не тот, что видит человек в поле «От».

## `dkim` DKIM

`category` mail · `see` spf, dmarc · `lessons` I1

Формы: DKIM

DomainKeys Identified Mail (RFC 6376): сервер отправителя подписывает письмо ключом домена, а
получатель проверяет подпись по открытому ключу из DNS этого домена. Верная подпись значит, что
подписавший домен берёт ответственность за письмо и подписанные части по дороге не меняли.
Подписывать может и не тот домен, что стоит в поле «От»: их сверяет DMARC.

## `dmarc` DMARC

`category` mail · `see` spf, dkim, domain · `lessons` I1

Формы: DMARC

Правило домена (RFC 9989, раньше RFC 7489), которое связывает проверки SPF и DKIM с адресом в
поле «От» и говорит получателю, как владелец домена просит обойтись с письмом, не прошедшим
проверку: без пожеланий (`none`), как с подозрительным, например в спам (`quarantine`), или
отклонить (`reject`). От писем с похожих доменов не защищает: у них свои записи.

## `cwe` CWE

`category` catalogs · `see` cve, owasp · `lessons` B1

Формы: CWE

Common Weakness Enumeration — каталог типов слабостей в программах и оборудовании, его ведёт
MITRE. CWE называет
класс ошибки, а не конкретную уязвимость: например, CWE-89 — SQL-инъекции.

## `cve` CVE

`category` catalogs · `see` cwe, cvss

Формы: CVE

Common Vulnerabilities and Exposures — общий список известных уязвимостей в конкретных
продуктах. Каждой даётся номер вида CVE-2021-44228, чтобы все говорили об одной и той же ошибке.

## `cvss` CVSS

`category` catalogs · `see` cve

Формы: CVSS

Common Vulnerability Scoring System — шкала тяжести уязвимостей от 0 до 10. Оценка складывается
из признаков: можно ли атаковать по сети, сложно ли это, нужны ли права и действия пользователя,
что страдает — конфиденциальность, целостность или доступность.

## `owasp` OWASP

`category` catalogs · `see` cwe, injection · `lessons` B1

Формы: OWASP, OWASP Top 10

Open Worldwide Application Security Project — открытое сообщество по безопасности
веб-приложений. Самый известный его документ — OWASP Top 10, список десяти главных классов
рисков; в выпуске 2021 года, на который ссылаются уроки, инъекции — пункт A03. В 2025 году вышел
новый выпуск.

## `mitre-attack` MITRE ATT&CK

`category` catalogs · `see` phishing, cwe · `lessons` I1

Формы: MITRE ATT&CK, ATT&CK

Открытая база знаний MITRE о тактиках и техниках атакующих, собранная по реальным атакам. У
каждой техники свой номер: T1566 — фишинг, T1566.002 — целевой фишинг со ссылкой.
